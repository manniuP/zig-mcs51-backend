# 四方对照：同一个 `add(u8,u8)->u8` 的 51 汇编（2026-10-30）

> 被测源（语义等价）：
> ```c
> unsigned char add(unsigned char a, unsigned char b) { return a + b; }
> ```
> ```zig
> export fn add(a: u8, b: u8) u8 { return a +% b; }
> ```
> 工具：Keil C51 V9.60.7（默认档与 OPTIMIZE(8,SPEED) 产物相同）、
> SDCC 4.6.0（`-mmcs51 --model-small`）、旧后端 compiler-017（`-OReleaseSmall`）、
> mcs2（zig-0.17 Debug 编译器，`-OReleaseSmall`）。

---

## 1. 四份产物并排

### Keil C51 —— 4B（最快也最小）

```asm
        MOV  A,R7        ; 参数 a 在 R7
        ADD  A,R5        ; 参数 b 在 R5
        MOV  R7,A        ; 结果回 R7
        RET
```
**ABI**：参数进寄存器文件（a→R7、b→R5），返回值 R7。全程零内存。

### mcs2（本次 M1 产物）—— 8B

```asm
_add_add:
        mov  a,0x82      ; a = DPL（SDCC 风格 ABI 直址）
        add  a,0x83      ; + DPH
        mov  0x82,a      ; 结果直写 DPL（「ret 前看一眼」单消费者优化）
        ret
```
**ABI**：参数 a→DPL(0x82)、b→DPH(0x83)，返回值 DPL。
零序言、零帧中转；差 Keil 的 4B 全在「参数与结果没进 R 寄存器文件」。

### SDCC 4.6 —— 9B

```asm
_add:
        mov  r7, dpl        ; 参数 a（DPL）搬到 R7
        mov  a, _add_PARM_2 ; 参数 b 在静态 PARM 区（不是 DPH！）
        add  a, r7
        mov  dpl, a
        ret
```
**ABI**：第一个字节 → DPL，**其余字节 → 静态 `_add_PARM_2` 区**（model-small 默认），
返回值 DPL。注意 `--sdcccall=1` 未改变第二参数的去处（实测产物相同）。

### 旧后端（compiler-017）—— 18B

```asm
_add_add:
        mov  a,dpl        ; a 落帧 _frk175
        mov  _frk175,a
        mov  a,sp         ; b 从栈上取（@spx1：sp-2 间接）
        clr  c
        subb a,#0x02
        mov  r0,a
        mov  a,@r0
        mov  _frk175+1,a
        mov  a,_frk175    ; 算术（两参数都过帧）
        add  a,_frk175+1
        mov  r4,a         ; 经 R4 中转
        mov  a,r4
        mov  dpl,a
        ret
```
**ABI**：a→DPL，b→栈（调用者入栈），返回值 DPL。
每个 AIR 值都落帧（`_frk175`、`_frk175+1`），再经 A/R4 往返——这是 18B 的全部来源。

---

## 2. 尺寸与构成

| 工具链 | 字节 | 参数位置 | 中间值位置 | 结果路径 |
|---|---:|---|---|---|
| Keil | **4** | R7 / R5 | 无（全在 A/Rn） | R7 |
| **mcs2** | **8** | DPL / DPH | 无（直址直算） | A → DPL |
| SDCC | 9 | DPL / 静态 PARM | A / R7 | A → DPL |
| 旧后端 | 18 | DPL / 栈 | 全量帧 `_frk` + R4 | A → R4 → DPL |

**结论**：四家的差距不在指令选择（都只有 `mov/add/ret`），而在**值位置**——
- Keil 的 4B = 参数与结果都在寄存器文件里，零字节搬运；
- mcs2 的 8B = 参数在 ABI 直址、结果直写返回位，**已消除全部帧中转**（旧后端的 10B 差距来源）；
- SDCC 的 9B = 多一条把 DPL 搬到 R7（它的算术左操作数习惯放 R7）；
- 旧后端的 18B = 每个 AIR 值都落帧 + 两次经 A/R4 中转。

## 3. 暴露的 ABI 事实（必须决策）

同一个函数，四家**三种**参数约定：

| | arg0(u8) | arg1(u8) | 返回 |
|---|---|---|---|
| Keil | R7 | R5 | R7 |
| SDCC | DPL | **静态 `_x_PARM_2`** | DPL |
| mcs2（当前） | DPL | **DPH** | DPL |
| 旧后端 | DPL | **栈** | DPL |

mcs2 的 `DPH` 与 SDCC 的 `_PARM_2` 不一致——**目前 mcs2 编出的函数不能直接与 SDCC 目标文件混链**
（参数 2 起对不上）。三个选项：

1. **跟随 SDCC model-small**（arg2+ → `_func_PARM_n` 静态区）：可与 SDCC 库/对象直接混链，
   代价是每函数多一个静态区符号、非可重入（与 SDCC 现状同病）；
2. **跟随 SDCC `--sdcccall` 新约定**（若其寄存器传参模式确认可用）：需要先实测确认；
3. **声明 mcs2 ABI 独立**（DPL/DPH/B/A 四字节进寄存器）：纯 Zig 工程可用、最省字节，
   但与 SDCC/Keil 对象互操作时需要胶水层。

> 建议：M1 阶段保持现状（纯 Zig 自洽，便于先把尺寸做好），**M3「老示例覆盖」前必须
> 定型**——因为 `usb_cdc_lib` 那条混合链路（SDCC 编 C + Zig 编主逻辑）依赖 ABI 一致。

## 4. 下一步的尺寸路线（由本对照直接读出）

- Keil 的 4B 靠「参数进 Rn」——对应研究清单 **P2-11（tied-def/交换）+ 值位置提升**；
- mcs2 到 Keil 量级的路径：`arg → Rn`（R7/R5 或 SWAP 到 Rn）+ `ret 结果留约定寄存器`，
  预计 add 可到 4–5B；
- 但先解决 ABI 决策（上节），否则字节赢了、互操作输了。
