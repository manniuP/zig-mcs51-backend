## 1. 目标与非目标

### 目标

1. 在干净 0.17 树上建立可维护的 MCS51 / MCS251 目标层；
2. 先恢复“能编译、能出 ihx/hex、能仿真验证”的最小闭环；
3. 再逐步覆盖老示例所需的 AIR 子集；
4. 251 的 LLVM 路线与 Zig 目标层解耦推进；
5. 所有阶段都有可重复的验收命令，不靠口头结论；
6. **最终定位（2026-10-29 确定）：mcs2 是「追尺寸 + 安全」的版本。**
   - 尺寸：终态对齐 Keil/SDCC 量级，手段按
     `E:/code/yuyan/docs/研究-Keil-LLVM-GCC优化策略对照与迁移清单-2026-10-29.md`
     的 P0–P4 清单逐项落地（窥孔框架已于 2026-10-29 先行移植，见
     `docs/mcs2进展-2026-10-29-条目流与窥孔.md`）；
   - 安全：Zig 安全模型落到 freestanding——`ReleaseSafe` 为默认开发档、
     边界/溢出检查保留并可关（随 `-O` 档位）、panic 路径在目标上可达
     （最小运行时：停机/诊断输出）、诊断齐全（每类检查有开关与可打印归因，
     先例：peephole 的 `diag` 统计）；
   - 两者由 §5.4 的 `-O` 档位分工：`ReleaseSmall` 追极限尺寸、
     `ReleaseSafe` 保安全，不混在一个默认档里硬权衡。

### 非目标

- 不在第一阶段追求尺寸追平 Keil（第一阶段不追；但追尺寸是终态目标，见目标 6）；
- 不把旧 `mcs` 后端整块复制进新树而不加标记；
- 不把“目标层通过”当成“后端可用”；
- 不在没有产物对比的情况下声称 LLVM 22 已收敛；
- 不把本机绝对路径、用户名写进文档或生成物。

## 3. 路线选择

### 3.1 三条路线

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A 干净重写** | 继续按 AIR 子集逐项实现 | 结构干净、可控 | 慢，短期不能替代旧后端 |
| **B 旧后端引导** | 把旧 `mcs` 后端作为 `bootstrap` 移入，再逐步替换 | 快速恢复老示例 | 旧结构回归，需明确隔离 |
| **C 混合** | 251 走 LLVM，51 保留自研或 SDCC | 251 更快可用 | 51 仍是难点，工具链分叉 |

### 3.2 选定策略

**主路线：A + C 并行。**

- 51：按 A 继续，但设置“引导门禁”：
  如果 M2 结束时仍不能覆盖老示例的核心子集，允许把旧后端作为
  `bootstrap` 移入，目录必须标 `bootstrap`，默认不参与新代码路径。
- 251：优先 C，使用 LLVM 22 的 MCS251 目标；自研 251 不作为主线。
- B 只作为应急方案，不作为默认架构。

**理由：**

- 51 没有可用的 LLVM 后端，完全依赖自研，必须保留可执行的恢复路径；
- 251 已有 LLVM 目标，重复造分配器投入产出比低；
- 先把“能跑老示例”与“结构干净”分开验收，避免互相绑架。

### 5.4 面向 `-O` 的优化策略

当前 `mcs2` 只有最小 MIR 发射切片，尚未接 AIR；此阶段不实现独立的优化开关。
接入编译器后，沿用 Zig 的 `Debug`、`ReleaseSafe`、`ReleaseFast`、
`ReleaseSmall` 语义，由优化模式选择 pass 与目标成本权重，不另造一套互不兼容的
`-Os`/`-O2` 参数。

| 模式 | 优化目标 | 初始策略 |
|---|---|---|
| `Debug` | 易调试、编译快 | 关闭跨块/循环变换；保留变量位置与源码映射；只做正确性必需的规范化 |
| `ReleaseSafe` | 安全优先 | 保留 Zig 安全检查；做常量折叠、死代码删除和局部简化；不做未经测量的代码膨胀变换 |
| `ReleaseFast` | 运行速度优先 | 降低周期数与昂贵访存优先；允许有限内联/循环变换，但每项必须通过尺寸上限与行为回归 |
| `ReleaseSmall` | 产物体积优先 | 最小化最终链接映像；避免循环展开和大规模内联；优先短指令、共享代码和紧凑帧布局 |

优化实现顺序：

1. **先做与目标无关的 IR 简化**：常量传播/折叠、复制传播、不可达块删除、
   死代码删除、分支折叠；所有模式共享这些不改变语义且通常不膨胀的变换。
2. **再做目标感知的指令选择与布局**：将立即数折叠进指令，选择合法的短跳转、
   位操作和寻址形式；优化帧槽、参数传递及短生命周期值，减少昂贵的 DSEG/XDATA
   来回读写。51 与 251 必须使用不同的指令/寻址成本，不可共用一张“每条指令等价”
   的成本表。
3. **寄存器分配后做受约束的 peephole**：检查标志位与寄存器活跃性后再删改指令；
   不以多次访存换少量代码，也不把仅在某个寄存器组/地址空间合法的序列误用于其他
   profile。
4. **最后测链接后的映像**：计入运行库、调用跳板、段对齐和链接器删除的代码；
   函数体字节数只作为定位回退的诊断指标，不能作为最终 `ReleaseSmall` 目标。

51/251 的高收益候选优先级：

- 首先消除多余的帧槽与 `mov`/`movx` 往返，减少指针反复物化；这是 `sumloop`、
  `memcpy4` 暴露出的已知尺寸热点。
- 做活跃区间分析与寄存器分配，避免当前“每个虚拟寄存器固定占一个 DSEG 字节”的
  垂直切片策略进入正式后端；溢出位置要按 DATA/IDATA/XDATA 分别计价。
- 加入短跳转选择、冗余跳转/标签消除、重复常量装载消除，以及可证明安全的
  load/store 合并；写 `volatile`、SFR、位地址或有别名可能的内存时不得合并/删除。
- 乘法等复杂操作先比较内联序列与运行库调用的**总映像成本及实测周期**；不能只拿
  调用跳板字节数与 Keil 内联主体比较。
- 循环展开、函数内联、全局代码合并先保持关闭或严格限量；51 的寄存器和 RAM
  紧张，静态估算“少几次分支”不代表实际更快，且常会明显增大固件。

每个性能改动至少同时报告：

- 51 与 251 分开的最终代码字节、静态 RAM/XDATA 用量；
- `add8`、`bits`、`mul8`、`sumloop`、`memcpy4` 的行为结果、代码尺寸及仿真周期；
- 老示例构建/行为回归结果，以及相对未优化基线的差值；
- 同一目标、同一输入、同一工具链版本和优化配置。没有周期计数器的环境只能报告
  指令/周期估算并标为估算，不能称为实测速度。

验收按目标模式分别进行：`ReleaseSmall` 以最终映像尺寸为主指标，运行周期作为
回归约束；`ReleaseFast` 以实测周期为主指标，尺寸设明确上限；二者都必须通过
行为回归。任何模式都不得以忽略 `volatile`/别名语义或删除安全检查来换取优化。
正式接入 `-O` 前，先建立可重复的周期和最终映像基线，再逐项启用变换，避免一次
引入多类 pass 后无法归因回退。

## 6. 验证与尺寸门禁

### 6.1 必需命令

```bash
# 目标层
zig run --zig-lib-dir lib tools/mcs2/target_probe.zig

# 51 最小闭环
python tools/mcs2/verify.py

# 51 独立汇编驱动
python tools/mcs2/assemble51.py build/out.asm --out-dir build --name out

# std 类型检查
zig build-obj -fno-emit-bin --zig-lib-dir lib lib/std/std.zig
```

### 6.2 尺寸门禁

- 主口径：函数体 CSEG，不含 export 跳板；
- 每次改动先量 `add8/bits/sumloop/memcpy4`；
- 51 与 251 分开报告，不互相代替；
- 0.17 的 51 当前比 0.16 大 28B（四项），在修复前不得宣称 51 改善；
- Keil 差距：51 按“函数 + 库”口径为 **3.77×**（101B），仅模块口径为 4.59×（83B）；
  251 为 7.95×（81B）。不得只引用 83B 而忽略 `?C?IMUL` 的 18B 库。

### 6.3 构建环境注意

当前工作区根目录可能带有 `Everyone:(DENY)(DC)` 的继承 ACL；`zig build` 会在
`configurer.exe` 阶段报 `AccessDenied`，这不是代码错误。

处理方式（不改源码语义）：

1. 把 `zig-0.17` 复制到可写临时目录；
2. 设置 `ZIG_LIB_DIR=<临时目录>/lib`，让编译器使用仓库自己的 `std` 与目标定义；
3. 无 `.git` 的副本加 `-Dversion-string=0.17.1`；
4. 用副本产物验证，改动仍落在仓库源码。

示例：

```bash
ZIG_LIB_DIR=<tmp>/lib zig build -Doptimize=Debug -Dversion-string=0.17.1
```

- 251 通过：29 个目标；

## 7. 决策门禁

| 门禁 | 触发条件 | 决策 |
|---|---|---|
| G1 | M2 结束仍不能覆盖四个基准 | 启用旧后端 `bootstrap`，并限定目录 |
| G2 | 51 尺寸继续高于 0.16 | 暂停加功能，先定位回退 |
| G3 | LLVM 22 与 24 产物不一致 | 不接 `zig cc`，保留 24 fork |
| G4 | 新后端无法在 ucsim 复现 `simtest` | 不宣称“可替代旧后端” |
| G5 | ZLS 与编译器版本不匹配 | 固定 0.17.0 release，不追 dev |

## 8. 禁止事项

1. 不把旧 `mcs` 后端无标记地复制进 `mcs2`；
2. 不用“能出 hex”代替“行为正确”；
3. 不用 251 的改善掩盖 51 的回退；
4. 不在未对比 22/24 产物时声称 LLVM 收敛；
5. 不把本机绝对路径写进文档、注释或生成物；
6. 不在未通过 ucsim 的情况下更新“老示例全通过”的结论。
