# 命令分派与函数表（模式选型 + 越界安全）

> ✅ **现行** —— 主题：C 的「函数表 + (enum,u16) 结构体」在 Zig/mcs2 里怎么写、以及**表下标越界**这条真实风险。
> 配套：`M2工作清单`（§2 M2.7、§3 后续）、`M2真机验收与三方对比`（§0 现状）。与它们**不重复**：本文件只管"分派模式 + 安全规则"。

## 0. 一句话

**C 那套「enum 选表 + 强转结构体」在 Zig 里有更安全的等价物（tagged union / switch / 表 + 统一签名），
但在 8051 上「用位运算算出来的下标去索引函数表」是**真会跳飞**的，必须显式挡。**

## 1. 三种等价写法（从小命令集到大命令集）

| 写法 | Zig 形态 | 什么时候用 |
|---|---|---|
| **switch 分派** | `switch (req) { .set => \|v\| …, else => … }` | 命令 <20 个；无间接跳转、不占表 Flash |
| **tagged union** | `union(enum){ set: u16, add: u16, ping: void }` | 取代 `(enum,u16)` + 强转；tag 与 payload 绑死，**不可能 cast 错** |
| **表 + 统一签名** | `const table = [_]*const fn (u16,u16) u16{ … };` | 命令很多、要按枚举批量挂；接口**只用定长标量**（结构体参数 mcs2 不支持） |

C 的 `Resp (*fun[N])(Req)` + `fun[req->cmd](*req)` 等价于上表第 3 行；
C 的 `(enum,u16) + 强转` 等价于第 2 行。第 1 行是"不想建表"时的默认解。

## 2. 越界风险：**会，而且是 8051 上最坏的那种**

C 里常见、也最容易出事的三行：

```c
u8 idx = (cmd | 0x80) & 0x0F;        /* 位运算拼出来的"枚举" */
resp = fun[idx](*req);               /* 直接当表下标 */
```

- **8051 没有 MMU、没有 fault**：下标错了就是 `jmp @a+dptr` / `push+ret` 跳到任意地址，
  表现为死机、乱跑、或"偶发正常"（取决于跳到的字节）。
- **Zig 也救不了**：数组下标只在 Debug/ReleaseSafe 查；本项目固件用 **`-OReleaseSmall`（不查）**。
- **`@enumFromInt` 是不检查的**（unchecked cast）；要检查用 `std.meta.intToEnum`（返回 error）。
  由 `&`/`|`/`~` 拼出来的值，**任何时刻都不该直接当枚举或表下标**。

### 安全写法（按推荐度）

1. **`switch` 穷尽**：编译期就把命令集列全，越界值走 `else`，**结构上不可能跳飞**（不占表 Flash）；
2. **表 + 兜底项（"非法值都指向同一个 handler"）**：见下面 §2.1 —— **前提是表长覆盖整个可达下标空间**；
3. **表 + 显式夹紧**：`const i = if (cmd >= table.len) return default; cmd;`；
4. **表 + `std.meta.intToEnum`**：协议字节 → `Cmd`，失败返回错误码；
5. **不要**：`table[@intFromEnum(@enumFromInt(x & 0x0F))]` —— 位掩码只是"看起来"安全。

### 2.1 兜底项做法（实战首选，但有一条硬前提）

把每个非法下标都映射到同一个处理函数：

```zig
fn h_bad(arg: u16, acc: u16) u16 { return 0; }     // 兜底：返回定义好的错误值
const table = [_]Handler{ h_set, h_add, h_sub, h_bad, h_bad, /* … 填满 2^n */ };

comptime {
    // 硬前提：表长 == 可达下标空间（掩码位宽由表长推出来，不允许手写漂移）
    std.debug.assert(table.len == 1 << @bitSizeOf(Idx));   // Idx = 掩码后的索引类型
}
export fn dispatch(cmd: u8) u16 {
    const idx: Idx = @truncate(cmd);         // 位宽由类型决定，不手写掩码
    return table[idx](0, 0);                 // 任何 idx 都 ≤ table.len-1 ⇒ 不会跳飞
}
```

**为什么它成立**：把"运行期检查"换成"编译期不变量"——`table.len` 与索引位宽被 comptime 断言绑死，
不存在"掩码改了、表没改"的漂移窗口。

**它什么时候会失效（三种）**：

1. **下标没被收窄**：`table[cmd]`（`cmd: u8`，表只有 16 项）→ `@bitSizeOf` 断言直接编不过，这是好事；
2. **表长不是 2 的幂**：`1 << n` 断言会挂 —— 要么补到 2^n，要么改用夹紧/switch；
3. **枚举有洞且最大值远超项数**（如 1,2,5,9 + 一个 0xF0）：表按**最大值**开，Flash 可能吃不下，
   这种就该用 `switch`（或 `intToEnum`）而不是表。

8051 上的账：表项 2 字节（代码空间）/ `xdata` 也行 —— 16 项 = 32 B 很划算；
**256 项 = 512 B**，8 位机上通常不可接受，那就是 `switch` 的地盘。

### 检查清单（写分派时逐条过）

- [ ] 表下标**来源只有两种**：`switch` 穷尽分派，或显式 `if (i >= len)` 检查；
- [ ] 没有把 `&`/`|`/`~`/`>>` 的结果直接当枚举/下标；
- [ ] 协议来的字节先 `intToEnum`（或范围检查）再进表；
- [ ] 表长与命令枚举的"最大值+1"用 `comptime assert` 绑死：
      `comptime { std.debug.assert(table.len == @typeInfo(Cmd).@"enum".fields.len); }`

## 3. mcs2 现状（2026-11-01 实测）

| 写法 | 状态 | 依据 |
|---|---|---|
| 语句形态 `if` 链 + `u8` 命令码 | ✅ 可跑 | `dispatch(2)=0x22`（71 项验收之一） |
| `&f` 单个函数指针变量 + 调用 | ✅ 且优化成直调 | `call_addr(9)=10` |
| `@ptrFromInt(u16)` 强转 + 调用（带参数/返回值） | ✅ | `call_ind=6`、`twice_ind=7` |
| `switch` **表达式**形态 | ❌ 块返回值（phi）未实现 | — |
| `switch` **语句**形态 / `enum` 参数 | ❌ 需 `switch_br` + 枚举宽度（M2.7） | — |
| `union(enum)` 作参数/返回 | ❌ 需 tagged union 布局 | — |
| 表 `table[i](x)`（运行期下标） | ❌ 需 2 字节元素带下标（M2.6c） | — |
| 结构体参数（`Resp f(Req)`） | ❌ 只支持 ≤4 字节标量 | — |

**落地建议（今天）**：命令码 `u8` + 定长参数 + `if` 链；单个函数指针变量可用。
表与 switch 分派要等 **M2.6c（2 字节元素带下标）** 和 **M2.7（switch_br + 跳转表）**。
