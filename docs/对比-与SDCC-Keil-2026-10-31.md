# 同源 C 三方对比：mcs2 / SDCC 4.6 / Keil C51 9.60

> ✅ **现行**（2026-10-31 实测）。适用：mcs2 的 51 代码尺寸与写法差距。
> 复现：`cd zig-0.17/tools/mcs2; python bench_compare.py`（Keil 列需 `KEIL_BIN`）

## 0. 口径

- **同一份 C 源码**（`tools/mcs2/bench_c/`），每个文件只放一个函数；
- **同一条汇编/链接链**：mcs2 与 SDCC 都经 `sdas8051 + sdld`，从 `.lst` 量
  「函数体首条指令 → RET」，所以字节数直接可比；
- **Keil** 用自身 listing 的 `MODULE INFORMATION: CODE SIZE`（单函数文件 = 函数体）；
- SDCC：`-mmcs51 --model-small -S`；Keil：`SMALL OPTIMIZE(8,SPEED)`；
- 函数体标签：mcs2 的函数体在 `_loop_<name>`，公开符号只是 3 字节 `ljmp` 别名，**不能当函数体量**。

## 1. 结果（字节）

| 用例 | 语义 | mcs2 | SDCC 4.6 | Keil 9.60 |
|---|---|---:|---:|---:|
| `add` | `u8 add(a,b) = a+b` | 7 | 8 | **4** |
| `sum` | `while(i<n) s+=i` | **19** | 20 | 17 |
| `memrt` | `buf[i]=i|0x40; return buf[i]&0x7F`（运行期下标） | 31 | **19** | 29 |
| `ringdemo` | kfifo 式环形缓冲（u8 索引 + 掩码） | 78 | 67 | **60** |
| `sum_to_fold` | 常量循环求和（PE 折叠） | **4** | 18 | 11 |

相对最好的对手：

| 用例 | mcs2 / 最好 | 说明 |
|---|---|---|
| add | 1.75× | ABI 差异（见 §2.1） |
| sum | **1.12×** | 37→19B：拷贝折叠 + `inc`/`dec` + 累加器/计数器进 R6/R7；**已优于 SDCC(20B)** |
| memrt | 1.63× | DPTR 复用后 37→31B（无自更新热点值，用不上寄存器） |
| ringdemo | 1.30× | 111→78B：拷贝折叠 + 寄存器分配 |
| sum_to_fold | **0.36×** | PE 编译期算完，循环整段消失 |

## 2. 差距归因（有汇编证据）

### 2.1 没有寄存器分配：每个值都以 DSEG 槽为中转

mcs2 的 `sum` 循环条件：

```asm
clr c
mov a,_mcs_v7      ; 2B
subb a,0x82        ; 2B
jnc L111
```

SDCC 同一处：

```asm
clr c
mov a,r5           ; 1B  ← 值常驻寄存器
subb a,r7          ; 1B
jnc 00103$
```

每做一次运算，mcs2 要「取到 A → 算 → 存回槽」三倍交通（约 6 B），SDCC/Keil 用
R5/R6/R7 直接算（2–3 B）。M2.12（相邻拷贝折叠 + `inc`/`dec`）与 **M2.13（自更新热点值进 R5/R6/R7）** 之后，
`sum` 已从 2.2× 降到 **1.12×**（19B，优于 SDCC 的 20B）：热点值独占寄存器后，
`mov a,r6 / add a,r7 / mov r7,a` 各 1 字节，不再经 DSEG 槽。
仍在线性扫描之外的场景（无自更新形态的值、跨基本块复用）没有分配，这是下一步。

### 2.2 ABI：arg0 在 DPL（为了和 SDCC 字节对齐）

`add` 只有 7 B，但 Keil 是 4 B：Keil 内部调用把参数放寄存器（`mov a,r7; add a,r5`），
mcs2 走 SDCC 边界 ABI（arg0=DPL、arg1=`_add_PARM_2`），得先 `mov a,0x82`。
等 M2.5 内部 ABI 落地，纯 Zig 间调用才能拿到 Keil 那种 4 B 形态。

### 2.3 DPTR 重算

`memrt` 里 `buf[i]=…; return buf[i]&…` 会算两遍 `dpl/dph`：

```asm
mov dpl,_mcs_v3
mov dph,#0x81
mov a,_mcs_v4
movx @dptr,a
mov dpl,_mcs_v3   ; ← 同一 base、同一 idx，重复计算
```

SDCC 把 `orl ar7,#0x40` 就地做掉、DPTR 只建一次。

**已修（2026-10-31，M2.11）**：发射层加 DPTR 状态跟踪——只有 xdata 访问才建地址，
相邻同 base 且 idx 是同一个 Byte 时跳过重建；下标 vreg 被改写、写 DPL/DPH、
遇到标签/跳转/ret 都作废状态。`memrt` 37B → **31B**（-16%）。



## 3. PE 是反向优势

`sum_to_fold`（循环 25 次的常量求和）三家都不做编译期求值：SDCC 18 B、Keil 11 B；
mcs2 的 `_fold` 把它折成 `mov 0x82,#0x2C; ret` = **4 B**（0.36×）。

这与 `docs/mcs2进展` §7 的 128 位阶乘结论一致（Keil 177 B / SDCC 561 B / 旧 Zig 646 B，
三家都不折），PE 轨（PE.3–PE.7）是尺寸上的差异化能力。

## 6. 总固件尺寸（含库，2026-10-31 晚补测）

> 上面量的是**函数体**。但 SDCC/Keil 把 16/32 位乘除下沉到库，站点只有几字节——只比站点会严重误判。
> 本节量**整份固件**：同功能编成完整程序，Δ = 用例 − 空程序基线。工具 `python fwsize.py`。

| 用例 | mcs2 | SDCC 4.6 | Keil 9.60 | Δ mcs2 | Δ SDCC | Δ Keil |
|---|---:|---:|---:|---:|---:|---:|
| baseline | 20 | 181 | 27 | 0 | 0 | 0 |
| u16mul | 86 | 229 | 55 | +66 | +48 | +28 |
| u16div | 128 | 241 | 122 | +108 | +60 | +95 |
| u32mul | 184 | 318 | 123 | +164 | +137 | +96 |
| u32div | 228 | 309 | 250 | +208 | +128 | +223 |
| i32div | 345 | 395 | 318 | +325 | +214 | +291 |
| sar32 | 147 | 227 | 60 | +127 | +46 | +33 |

**结论修正**：把库算进去，32 位乘除的差距是 **1.2–1.6×**（u32div 甚至比 Keil 小），
不是按站点比出来的 6–20×；真正落后的只剩小算子的内联实现（u16mul、sar32），
因为 mcs2 每个操作数都要先物化一份（`wideOperand`）——M2.14 活跃期/拷贝消除要解决的正是它。
另外 mcs2 的空程序只有 20 B（bare-metal 无 crt0/库），SDCC 181 B、Keil 27 B。

**两个测量坑**：C 侧操作数必须是 volatile 全局（否则编译期折叠 → Δ=0）；
Keil 命令行链接要逗号串成一整串且必须显式链 `STARTUP.A51`，尺寸读 `.M51` 的 `Program Size: code=N`。
