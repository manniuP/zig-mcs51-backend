## 1. 真机逐项验收（`realcheck.py`）

### 1.1 为什么不是「一个固件跑全部」

mcs2 的 vreg 是**每函数一块静态 DSEG 槽**（M2.14 活跃期分析之前不做复用），
直址区只有 `0x30-0x7F`（80 B），而一组 u32 除法要 ~26 B。所以 48 项按**源文件**分成 15 组，
每组一个固件。这不是脚本偷懒，是后端现状的真实约束。

### 1.2 结构

```
每组固件 = 汇编外壳（crt0 + UART1 初始化 + 摆参 + lcall + 打印） + 该文件的全部 Zig 函数
            ↓ 同一条链
        zig build-obj → .asm → sdas8051 → .rel → sdld → .ihx
```

- 外壳必须用汇编：**mcs2 还没有 `.call`（M2.5）**，Zig 侧连函数都不能互相调用。
- 每条用例**同时**写 xdata（`0x8000 + i*4`）和 UART 打印：
  xdata 供 `--sim` 在 ucsim 里逐字节核对，UART 供真机核对——**算术代码是同一份**。
  两种模式只有 `_putw`（等不等 TI）不同：ucsim 的 SBUF/TI 时序不可靠，等它会卡死。
- `--sim` 结果：**15 组 48 项全过**（`python realcheck.py --sim`，约 1 分钟）。

### 1.25 免按 RST：固件自己跳下载模式（**本机 AI8051U 实测失败，已默认关闭**）

> ❌ **结论：这条路在这颗芯片上不成立。** 写 `IAP_CONTR = 0xC7` 的 0x60 确实触发了复位
> （串口上能看到复位残留字节 + 之后程序从头跑），但**没有进入 ISP**，于是 AiCube 永远等不到握手、
> 报"下不进去"；更糟的是它让每次下载都被打断。现在 `realcheck.py` 默认**不加**这段，
> 只有 `--isp` 才编进去（留作以后拿到 AI8051U 的 ISP 进入条件再试）。
> 待查：AI8051U 头文件里除了 `SWBS`(bit6)/`SWRST`(bit5) 还有个 `SWBS2`(bit3)，
> 可能 251 核进入 ISP 需要它；也可能需要先关 EA / 或在 ISP 区存在的前提下。

原始设计（**未在本机生效**，仅存档）：

每组固件末尾都挂了这么一段（realcheck.py 的 ISP_WATCH）：

    ; ---- 串口收到字节就软复位进 ISP（下载模式）----
    jb 0x98,_isp_hit      ; SCON.RI（位地址 0x98）= 收到字节
    ljmp _again           ; 没收到 → 继续循环打印
_isp_hit:
    mov a,0x99            ; 读 SBUF，硬件清 RI
    mov 0xC7,#0x60        ; IAP_CONTR：SWBS=1（从 ISP 区启动）+ SWRST=1（软复位）
    sjmp .                ; 芯片复位 → ISP bootloader 等下载

- IAP_CONTR = 0xC7 是 **AI8051U 官方头文件的值**（stc8/AI8051U-DEMO-CODE 里的 AI8051U.h 第 82 行；
  SWBS=bit6、SWRST=bit5 → 写 0x60）。STC89/STC8 老家族是 ISP_CONTR = 0xE7，别混。
- 认「**任何字节**」而不是魔法字：AiCube 的下载握手最早发 0x7F，但它按**自己的下载波特率**发
  （可能 2400），在 115200 下收到的是乱码——只认同一个值会漏。
- 于是每组流程变成：**AiCube 选文件 → 点下载 → 固件收到握手字节就自己进 ISP → 下载**，
  不用再断电/按 RST。手动触发：python realcheck.py --dl COM14。
- 坑：jb/jnb 射程只有 ±127，回跳 _again 必须用 ljmp（否则 sdas 报 Branching Range Exceeded）。

**唯一没采到的 setbit**：它自己的用例代码把 **SCON 改成 0x00 再置 TI**（`SCON.* = 0; SCON.* |= 2`），
而外壳正是用同一个 SCON 发字符——那一条的打印自然丢了（ucsim 里能过是因为仿真不关心 SCON 模式）。
**不是后端算错**，是「用 UART 控制寄存器做位操作测试」与「用 UART 输出」互相干扰；
要复验就把它改成对 0x20–0x2F 的可位寻址 RAM 做 setb/clr（后端指令形态相同）。

> 采集方式：每组烧一个固件（一个测试源文件），固件循环打印 `名字=HEX`；
> 主机侧 `realcheck.py --watch COM14 --open 0.6 --close 5.4` 用 10% 占空比轮询，
> 其余时间把串口让给 AiCube 下载。中途踩到的坑：`job_kill` 只杀 pwsh 外壳，
> python 子进程会成孤儿一直抢串口（已加 PID 打印 + 时长上限）。

### 1.3 上板要做的三件事

1. 插上板子（现在 `Get-PnpDevice -Class Ports` 是空的，AiCube 也没在跑）；
2. 逐组烧 `<workspace>/build/fw/real_g*.ihx`（15 个；AiCube-ISP 可批量）；
3. `python realcheck.py --read COM8 --baud 9600`（或 `--fosc 40000000 --baud 115200`）。

> **默认板 = AI8051U**：UART1 走 **P3.0(RxD)/P3.1(TxD)**、Timer2 1T 作波特率，
> 配置照抄 `zig_t0print`（真机 COM8@115200 验证过的那套）；40 MHz/115200 → `T2H:T2L = 0xFFA9`。
> 换 STC8H 用 `--board stc8h`（P3.6/P3.7 + Timer1，45.1584 MHz/9600 → TH1=0x6D）。
> 两种波特率都已出固件（`_115200`/`_9600` 后缀）；若 115200 是乱码，先试 9600 那套。
> **AI8051U 烧 8 位固件时会自动把 CPU 指令模式切成 8-Bit**（ISP 的硬件选项随下载更新，
> 见 `mcs251/docs/13`：8 位模式从 0x0000 取指，实测可跑）；要回到 251 的 demo 就重烧 251 固件。
> 真机读数的判据与 ucsim 完全同源（同一张 `CASES` 表）。

### 2.05 总固件尺寸（**含库**，2026-10-31 补测，`python fwsize.py`）

上一节量的是**函数体**；SDCC/Keil 把 16/32 位乘除下沉到库，站点只有几字节，库另算。
所以再量一遍**整个固件**：同一功能编成完整程序（固定参数算一次 → 写 volatile 全局 → while(1)），
「总 ROM」= .ihx 数据字节；Δ = 用例 − 空程序基线。

| 用例 | mcs2 总 ROM | SDCC 4.6 | Keil 9.60 | Δ mcs2 | Δ SDCC | Δ Keil |
|---|---:|---:|---:|---:|---:|---:|
| baseline（空程序） | **20** | 181 | 27 | 0 | 0 | 0 |
| u16mul | 86 | 229 | 55 | **+66** | +48 | **+28** |
| u16div | 128 | 241 | 122 | **+108** | +60 | +95 |
| u32mul | 184 | 318 | 123 | **+164** | +137 | **+96** |
| u32div | 228 | 309 | 250 | **+208** | +128 | +223 |
| i32div | 345 | 395 | 318 | **+325** | +214 | +291 |
| sar32 | 147 | 227 | 60 | **+127** | +46 | +33 |

**读法（和上一节的 6×–20× 不同，以这张为准）**

1. Δ 里含**库**：SDCC/Keil 的 Δ = 调用站点 + 被拉进来的库函数，mcs2 的 Δ = 内联模板（无库可拉）。
   于是 32 位乘除的差距从「站点比」的 6–20× 收窄到 **1.2–1.6×**
   （u32mul 164 vs 137 = 1.20×；u32div 208 vs SDCC 128 = 1.63×，但 **比 Keil 的 223 还小**；
   i32div 325 vs 291 = 1.12×）。**"mcs2 的 32 位模板离库版本不远"** 才是真相。
2. 真正落后的只剩**小算子内联对拼**：u16mul +66 vs +48/+28、sar32 +127 vs +46/+33
   —— 差距来自 `wideOperand` 的先物化后算（每操作数 n 字节拷贝 + 常量逐字节 imm），M2.14 的目标。
3. mcs2 的**空程序只有 20 B**（bare-metal，无 crt0/库），SDCC 181 B / Keil 27 B；
   所以小工程里 mcs2 的绝对体积极有优势，算子一多才会被拷贝吃掉。

**测量本身踩的两个坑**（复现时注意）：
- C 侧的操作数必须写成 **volatile 全局**，否则整个运算被**编译期折叠**，Δ 直接是 0（第一版就是这样，u16mul Δ=+1）；
- Keil 命令行链接要 `BL51 p.OBJ,STARTUP.OBJ,<LIB>\C51S.LIB`（**逗号串成一整串**，分开传 argv 不认），
  且 C 程序必须显式链 `STARTUP.A51`（uVision 会自动加，命令行不会）；尺寸读 `.M51` 末尾
  `Program Size: ... code=N`。

### 2.1 怎么读这张表（**别只看倍率**）

1. **粗体行不是同一个东西**：SDCC/Keil 把 16/32 位乘除下沉到**库函数**，
   站点只有 `ljmp __mulint`（9 B）/ `lcall ?C_MUL`（3 B）——库本身几百字节另算；
   mcs2 因为**没有 call（M2.5）**，每处都内联整段模板。所以「6×–20×」的差距主要是
   **内联 vs 库调用**，不是模板写得差多少。
2. **公平的内联对拼**：u32add（62 vs 29，2.1×）、u32 移位（1.7×）、cmp32（2.0×）、
   sar32（2.1×）——这些都是双方都内联的，差距来自 mcs2 的「先物化再算」拷贝
   （`wideOperand`）与常量逐字节 store，正是 M2.14 的目标。
3. **SDCC 的两个「聪明」值得抄**：`sexcmp` 只花 21 B —— SDCC 看出「i8 符号扩展后与 -1 比」
   等价于「i8 与 -1 比」，把 32 位比较降成 8 位；mcs2 老老实实做 4 字节链（66 B）。
4. Keil 的 ABI 设计让 16 位乘是**一条 lcall**（参数/返回都在 R4–R7），所以只有 3 B。

## 3. USB-CDC 混编（`interop/`）

### 3.1 结论先行

| 问题 | 结论 |
|---|---|
| C(SDCC) 与 Zig(mcs2) 能链在一起吗 | **能**。sdcc 当链接器，Zig 的 `.rel` 与 C 的 `.rel` 同链，符号全解析 |
| 调用方向 | **双向都通（M2.5 之后）**：C→Zig 与 Zig→C 已实测（`zig_calls_c(0x10)` = 0x21，ucsim 跑过） |
| 单字（≤4 字节参数）接口 | **两种内存模型都安全**：参数/返回全在 DPL/DPH/B/A |
| 多字（>4 字节）接口 | **必须让 C 侧用 `--model-small`**：`PARM_2+` 溢出区在 large 模型下被 SDCC 放进 **xdata**（`mov dptr,#_fn_PARM_2` + `movx`），而 mcs2 把它放 **DSEG** |
| 现在能跑吗 | 仿真里**跑通了**（见下），USB 枚举要真机 |

### 3.2 实测（`python interop/build.py`）

`--model-small` 的 C 侧调用序列与 mcs2 逐字对齐：

```asm
    mov dpl, #0x21          ; 单字节 arg0
    lcall _zig_cdc_mix
    mov _zig_cdc_hash_PARM_2,#0xff   ; 4 字节 arg1 → DSEG（mcs2 也读这里）
    mov (_zig_cdc_hash_PARM_2 + 1),a
    mov (_zig_cdc_hash_PARM_2 + 2),a
    mov (_zig_cdc_hash_PARM_2 + 3),a
    mov b,  #0x34                   ; 32 位 arg0 的高字节
    lcall _zig_cdc_hash
```

`--model-large` 则变成 `mov dptr,#_zig_cdc_hash_PARM_2` + `movx @dptr,a` —— 与 mcs2 的 DSEG 区**不匹配**。

仿真跑（`ucsim_51 -t 8052`，small 模型镜像）：

| 变量 | 期望 | 实测 |
|---|---|---|
| `out8 = zig_cdc_mix(0x21)` | `0x8C` | `0x8C` ✅ |
| `out32 = zig_cdc_hash(0x12345678, 0xFF)` | `0x468ACF77` | `0x468ACF77` ✅ |

### 3.3 对 `examples/ai8051u/usb_cdc` 的落地建议

- 该示例用 `-mmcs51 --model-large`（xdata 指针为主）。**Zig 侧的接口保持「总参数 ≤4 字节」**
  （如 `u8`/`u32` 单参、`u8+u8`），就完全避开 PARM 区差异；
- 若要传更多参数：给这个示例单独加一个 `--model-small` 的编译单元（把回调放进去），
  或者等 mcs2 支持 `--model`（按 C 侧模型把 PARM 放 xdata）——列为后续项；
- 加钩子的最小改动：在 `usb_cdc_all.c` 的回调里 `extern unsigned char zig_cdc_mix(unsigned char);`，
  调用点拿返回值即可（方向只能是 C→Zig）。
