# 方案：把编译错误里的改写建议从「骨架」升级为「可编译代码」

> 状态：**设计稿，待实施**（2026-11-04）。本轮只写方案，不改编译器代码。
> 适用：`zig-0.17` 的 mcs2 后端，8051（51）先行，251 押后。
> 前置：`docs/待推进-2026-11-02.md`、`docs/M2工作清单-2026-10-31.md`。

---

## 1. 问题与目标

现有 `src/codegen/mcs2/diag.zig` 已能在编译错误里输出**带真实函数名、真实参数名、真实类型的 Zig 代码骨架**，但表达式位置仍是占位注释：

```zig
if (/* 原基准条件 */) return acc + /* 原基准返回值 */;
return rec_bad__tail(/* 原递归实参 */, acc + /* 原调用后的运算 */);
```

用户要的是「直接提示代码该怎么改」，即**生成完全填好、可直接编译、语义等价**的代码，而不是让人自己填。

**目标**：对一类受限但常见的形态（简单直接自递归，递归调用后只有一次可结合的二元运算），从 AIR 还原出完整代码；其余形态**明确回退**到现有骨架，绝不生成猜测代码。

**非目标**：通用 Zig 源码重写器、跨函数互递归、带副作用的递归、浮点、251 发射器、跨版本 AIR 兼容层。

## 2. 现状链路（实施时的落点）

| 位置 | 作用 |
|---|---|
| `src/codegen/mcs2.zig` 的 `.call` 分支 | 用 `callee_nav` 与 `self.nav` 比较识别直接自递归；`tailRetOf()` 先把尾调用转成 `ljmp`；非尾自递归在 `lcall` 前调 `failFix(.tail_rec, ...)` |
| `src/codegen/mcs2.zig` 的 `failFix()` | 从 `func_type.param_types` 取类型，从 `navSrcLoc().baseline.resolve()` + `File.getSource()` 抽源码里的真实参数名，再调 `diag.render()` |
| `src/codegen/mcs2/diag.zig` 的 `render()` | 按 `Kind` 拼建议文本；`.tail_rec` 目前是骨架 |
| `tools/mcs2/mcs2.py` 的 `check_reject()` | `kind="reject"` 用例用 `want_err` + `want_code` 断言错误输出里出现指定代码片段 |

**关键事实**：`failFix` 触发时 `emitBody` 已中止，但 `self.air.instructions` 全表仍在内存，可离线遍历；`MCS2_DUMP_AIR` 的逐条打印会在拒绝点截断，**不能**作为分析依据。

**可复用**：`instUsesValue()` 已示范各 AIR tag 的载荷形态（`bin_op` / `un_op` / `ty_op` / `br` / `unwrapCall`），表达式渲染器按同一套白名单解析。

## 3. 可识别形态（第一阶段）

以 `examples/mcs51/src/rec.zig` 为例，完整 AIR（拒绝前的全表）：

```
arg(0)
block(1)
  cmp_lte(2)  → cond_br(5)
  ret_safe(3) → 基准返回值
  br(4)
sub_safe(6)   → 递归实参 n - 1
call(7)       → 自调用
add_safe(8)   → 调用后运算 call + 1
ret_safe(9)
```

抽象成：

```zig
export fn f(P) R {
    if (C) return B;      // 基准分支
    return f(A) ⊕ K;      // 递归分支
}
```

**七条硬约束，全部满足才变换**：

1. 函数内恰好一个非尾自调用（`.call` 目标 nav == 当前 nav）。
2. 调用结果只有一个消费者，且是一次二元运算 `R = call ⊕ K`；`K` 不含该结果、不含副作用。
3. 该运算的结果直接位于 `ret`。
4. 基准分支的 `ret` 操作数是常量或不含递归调用的简单表达式。
5. 递归实参表达式 `A` 只依赖本函数参数与常量，不依赖局部变量。
6. `⊕` 属于**可交换、可结合、有单位元**的运算：`+` / `+%` / `*%` / `|` / `^`（`&` 需单独证明）。`2 - call`、`call / 2`、`call << k`、比较、逻辑短路等**一律不放行**。
7. 递归路径上无 `store`、无外部 `call`、无 volatile 访问、无局部变量读写。

满足约束时设 `e` 为 `⊕` 的单位元，生成：

```zig
export fn f(P) R {
    return f__tail(P, e);
}
fn f__tail(P, acc: R) R {
    if (C) return acc ⊕ B;
    return f__tail(A, acc ⊕ K);
}
```

等价性依据：设递归深度为 `d`，原结果 = `B ⊕ K ⊕ … ⊕ K`（`d` 次）；尾版 `acc` 从 `e` 起每步 `acc ⊕ K`，基准再 `⊕ B`。`⊕` 可交换可结合且 `e` 为单位元时两者相等。后端已把尾调用编成 `ljmp`（等价循环），所以生成代码能编且不增栈深度。

## 4. 四层实现

### 4.1 AIR 表达式渲染器（新增 `src/codegen/mcs2/air_expr.zig`）

- 输入 `Air.Inst.Ref` + 上下文（参数名表、函数类型、当前函数名），输出 Zig 表达式字符串。
- 按 tag 白名单分派：
  - `arg` → 参数名（来自 `paramNamesFromSource`，取不到用 `a0/a1`）
  - 常量 → 字面量；`load` → 变量名
  - `add/sub/mul/div/rem/bit_and/bit_or/xor/shl/shr/cmp_*` → `lhs <op> rhs`
  - `int_cast` / `trunc` → `@intCast(...)` / `@truncate(...)`
  - `call` → `名(实参)`
  - `block` → 递归渲染其 body
  - `add_safe` 等安全档 tag 渲染成 `+`（不是 `+%`）；`add_wrap` 才渲染 `+%`，保持与原码语义一致
- **失败即回滚**：遇到未覆盖 tag、载荷布局不明、或含副作用，返回 `null`；调用方据此回退骨架。**禁止猜测代码**。
- 单测覆盖：每个白名单 tag 一条；未知 tag 一条（断言返回 null）。

### 4.2 模式识别（新增 `src/codegen/mcs2/tail_rec.zig`）

- 遍历 `self.air.instructions`，按 §3 的七条约束匹配，产出：
  `Pattern { cond, base, recur_args, op, rhs, unit, params, ret }`
- 只做**结构匹配**，不做数据流求解；任何一条不满足返回 `null`。
- 明确记录「为何不匹配」的枚举原因，便于在错误信息里给一句人话（例如「调用后是减法，不能安全改成累加器」）。

### 4.3 双路代码生成（改 `diag.zig`）

- `Kind` 增加 `.tail_rec_exact`；`render()` 增加 `?Pattern` 参数。
- 有 Pattern → 输出**完全填好**的尾递归代码；无 Pattern → 输出**现有骨架**，并在末尾加一行「本函数含不可自动变换的形态，以下骨架需按实际逻辑补全」。
- 两类输出都加稳定边界标记（如 `// mcs2-fix-begin` / `// mcs2-fix-end`），供验收脚本提取；标记不含路径与隐私信息。
- 其余六类建议（`mul_safe` / `data_addr` / `const_multi_dim` / `switch_wide` / `ind_call_args` / `param_over4`）本期不动，后续按同样的「渲染 → 匹配 → 生成」思路扩展。

### 4.4 回写验证（改 `tools/mcs2/mcs2.py`）

新增 `kind="fix_roundtrip"` 用例，流程：

1. 编译触发拒绝，**从 stderr 里按边界标记提取代码块**；
2. 把代码块写成临时 `.zig`（放 `tools/mcs2/build/`，已忽略）；
3. 用同一个 mcs2 编译器编译该代码 → `driver_call` 摆参 → `sdas/sdld` → `ucsim` 跑；
4. 断言**能编译、行为与原函数期望值一致**。

这是最强门禁：既防止「生成的代码看着对、其实编不过」，也防止语义不等价。尺寸档产物不受影响（生成只发生在错误路径）。

## 6. 验收口径

- 现有 **150 项全绿**、尺寸门禁 `_add` 7 B、C↔Zig 混链门禁不回退。
- 新增至少：
  - 3 个 `fix_roundtrip` 用例：`+1` 累加、`*%2` 累加、`+%` 累加；
  - 2 个「不可变换」用例（`2 - f(n-1)`、含 `store` 的递归），断言**回退骨架**且错误里给出原因；
  - `air_expr.zig` 单测全绿。
- 尺寸档（`-OReleaseSmall`）产物与实施前**逐字节一致**：建议只在编译失败路径生成。
- 错误信息不得含本机绝对路径、用户名、邮箱；路径一律相对。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| AIR tag / 载荷布局随上游版本变化 | 白名单解析 + fail-closed；单测钉住当前 tag 集合；不解析未知 tag 的 `data` |
| 生成代码语义不等价 | 只放行可交换可结合有单位元的运算；其余明确回退，不硬生成 |
| 局部变量 / 作用域 | 第一阶段要求递归路径不含局部变量读写，否则回退 |
| 参数名与签名不自洽 | 复用 `paramNamesFromSource`，取不到时全链路统一用 `a0/a1` |
| 生成代码与原文件同编时符号重复 | 回写验证把代码块写成独立临时文件，单独编译 |
| 建议代码本身触发同样的拒绝 | 尾递归会被 `tailRetOf` 转成 `ljmp`，不触发非尾拒绝；回写验证会兜住意外 |
| 命令行渲染给多行消息加对齐空格 | 属 Zig 命令行行为，不改消息内容；必要时用边界标记供工具提取 |

## 9. 待拍板的三个问题

1. 第一阶段范围是否限定为「直接自递归 + 一次可交换二元运算」？**建议：是**，先把正确性与回写门禁做扎实。
2. 生成代码定位为「给人复制」还是「工具可自动回写」？**建议：两者都做**，自动回写只用于验收脚本，不改写用户源码。
3. 不可变换时输出什么？**建议：回退现有骨架 + 一句具体原因**，既不撒手不管，也不假装能自动改。
