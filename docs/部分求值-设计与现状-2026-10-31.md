# mcs2 部分求值（PE）设计与现状

> ✅ **现行**（2026-10-31）。适用：`zig-0.17/src/codegen/mcs2*`。
> 配套：`docs/mcs2进展-2026-10-30-M2控制流.md`（M2/PE 工作清单）、`docs/迁移计划.md`

---

## 0. 一页结论

1. **激进优化默认关闭**，只对**函数名以 `_fold` 结尾**的函数尝试；
2. **任何 SFR/xdata 读写都拒绝折叠**（硬件时序/副作用不可折），唯一例外 `store_dir 0x82`（u8 返回值 ABI 出口）；
3. 折叠做法：在 MIR 上直接**解释执行**整个函数，走到 `ret` 就把函数体替换成「常量写回 + ret」；
4. 验收：`sum_to_fold()` → `mov 0x82,#0x2C; ret`（4 字节，循环/比较/分支全部消失）；
5. 局限：无参数、无内存读、无调用、步数上限 20 万；`while(true)` 需要「块终止传播」支持（已加）。

---

## 1. 规则表

| 条件 | 结果 |
|---|---|
| 函数名不以 `_fold` 结尾 | **不折**（默认） |
| 名字以 `_fold` 结尾，但有 `load_dir/load_xdata/store_xdata` | 拒绝 |
| 名字以 `_fold` 结尾，但有 `store_dir` 且地址 ≠ 0x82 | 拒绝 |
| 有 `push/pop/reti/halt` | 拒绝 |
| 有参数（`arg_cursor != 0`） | 拒绝 |
| 中断函数 | 拒绝 |
| 其它（纯 u8 计算 + 分支/循环） | **折叠** |

折叠成功后的函数体 = 每个被写过的 xdata 地址/直址各一条「常量写回」+ `ret`；
vreg 全部消失，`nregs` 重置为 1。

## 3. 折叠器骨架

```zig
fn foldPure(self: *Lower) codegen.Error!bool {
    const ops = self.ops.items;
    if (ops.len == 0) return false;

    // 1) 硬件访问一律不折；DPL(0x82) 例外（u8 返回值出口）
    for (ops) |op| switch (op) {
        .load_dir, .load_xdata, .store_xdata, .push, .pop, .reti, .halt => return false,
        .store_dir => |x| if (x.addr != 0x82) return false,
        else => {},
    };

    // 2) 解释执行（regs[256] / dirs[256] / xdata 写表；步数上限 200_000）
    var regs: [256]u8 = undefined;  @memset(&regs, 0);
    var dirs: [256]u8 = undefined;  @memset(&dirs, 0);
    var wrote_dir: [256]bool = undefined; @memset(&wrote_dir, false);
    var pc: usize = 0; var steps: usize = 0; var folded = false;
    while (pc < ops.len) {
        if (steps >= 200_000) return false;
        steps += 1;
        switch (ops[pc]) {
            .imm  => ...            // 写常量
            .mov  => ...            // 拷贝
            .add  => ...            // a +% b
            .sub  => ...            // a -% b
            .dec  => ...            // 计数器 -1
            .store_dir   => ...     // 记进 dirs[]，标记 wrote_dir
            .store_xdata => ...     // 记进 xdata 写表（后写覆盖前写）
            .label => pc += 1,
            .br   => pc = findLabel(t) orelse return false,
            .br_ifnz / .br_ifz => ...
            .cmp_br => ...          // foldCc(cc, a, b)
            .dec_br_nz => ...       // djnz 语义
            .ret => { folded = true; break; },
            else => return false,
        }
    }
    if (!folded) return false;

    // 3) 物化：每个写过的地址各一条立即数写回 + ret
    //    直址直接 `.imm{ dst = .{.dir = addr} }`（PE.2：mov dir,#imm）
    //    xdata 用 vreg(0) 中转后 store_xdata
    ...
    return true;
}
```

关键子函数：`foldGet/foldSet`（Byte → 值）、`foldCc`（条件码）、`findLabel`（跳转目标）。
`Byte` 的四种形态：`vreg / dir / sym / imm`；`sym` 一律拒绝（外部内存）。

## 4. 怎么写（用法）

**A. 函数级标记（现在唯一可用）**

```zig
export fn sum_to_fold() u8 {
    var s: u8 = 0;
    var i: u8 = 0;
    while (i < 25) : (i += 1) s +%= i;
    return s;
}
```

产物：`mov 0x82,#0x2C` / `ret`（`300 & 0xFF = 44`）。

**B. 语言级 `comptime`（Zig 自己折，不经过后端）**

```zig
const v = comptime computeFact(25);   // 直接得到常量
```

**C. `{}` 区域标记——目前做不到**：Zig 的块标签不进 AIR，后端看不到。
要区域粒度得等**函数调用（M2.5）**落地后，加一个包装约定（预留名 `mcs2Fold`）：

```zig
mcs2Fold(struct { ... });   // 后端识别这个调用 → 把里面的代码当独立可折单元
```

## 5. 已知坑

1. **`store_dir` 曾漏挡** → UART 初始化/发送（写 SBUF）被整段折叠，延时与移位时序全丢。现在按 §1 拒绝。
2. **`while(true)` 没有 `ret`**：`generate()` 只在「body 未终结」时报错；`.block/.loop` 已做终止传播
   （body 终结且无人 break 到块尾 → 视为不落空）。
3. **常量不再物化 vreg**（`Byte.imm`）：`add a,#0x01` 直出；与 0 比较时 `xrl` 可省。
4. **PE 在 `rotateDjnz()` 之后跑**，所以先做 djnz 形态再折叠；折叠会用常量写回覆盖一切。
5. **DPL 例外**：`store_dir 0x82` 是返回值出口，允许；其它直址一律拒绝。

## 7. 与 M2/P1 的关系与 TODO

- PE 依赖 P1 的「立即数直接做操作数」（`Byte.imm`）；反过来 PE 是尺寸的差异化能力（Keil/SDCC/Zig 都不折）。
- 预留接口（写在 `docs/mcs2进展-2026-10-30-M2控制流.md` §8）：

  - [ ] 带参数特化（实参 comptime 已知 → 先特化再折）
  - [ ] 数组/常量下标读写（PE.4）
  - [ ] 折叠预算/代码膨胀阈值可配
