# 运行时模板库（rtlib）：标准算子改用手写汇编

日期：2026-11-06　范围：`src/codegen/mcs2/rtlib.zig`、`mcs2.zig`（移位分支与文本拼装）、
`mir.zig`（新增 `lea_r_vreg`）、`mcs51.zig`（发射）、`tools/mcs2/mcs2.py`（门禁）

## 1. 为什么要有这一层

`bincompare.py` 把三方产物转成 `.bin` 后逐算子比，暴露的事实是：**后端生成的
内联代码在固定算法上先天吃亏**，而且不是靠调优能追平的。以 32 位算术右移为例，
后端展开出来的形状是：

```asm
    mov a,_mcs_v7      ; 2 B
    rrc a
    mov _mcs_v7,a      ; 2 B
    mov a,_mcs_v6      ; 2 B
    ...                ; 4 字节 × 3 轮
```

三处浪费全是「通用代码」的固有代价：

| 浪费 | 成因 | 代价 |
|---|---|---|
| 槽往返 | 值在 DSEG 槽里，每次移位都要先进 A 再存回 | 每对 `mov` 4 B，12 对共 48 B |
| 不循环化 | 常量次数被完全展开成 39 条指令 | 相对 `djnz` 循环多 48 B |
| 输入→输出复制 | 结果必须落到新槽 | 4 条 `mov direct,direct` 12 B |

手写模板把这三样一次性算清：值用 `@r1` 直连槽、`djnz` 循环、原地更新。

## 2. 现在的形状

```asm
; 站点（7 B）
    mov r1,#<(_mcs_v3)     ; 槽基址 + 3 = 最高字节
    mov r0,#0x03           ; 移位次数
    lcall _mcs_rt_sar32

; 模板（24 B，整个汇编单元一份）
_mcs_rt_sar32:
L_mcs_rt_sar32:
    mov a,@r1
    mov c,acc.7            ; 每轮重新取符号位，否则就成逻辑右移
    rrc a
    mov @r1,a
    dec r1
    mov a,@r1
    rrc a
    mov @r1,a
    dec r1
    mov a,@r1
    rrc a
    mov @r1,a
    dec r1
    mov a,@r1
    rrc a
    mov @r1,a
    inc r1
    inc r1
    inc r1
    djnz r0,L_mcs_rt_sar32
    ret
```

关键决定是**直连槽而不是走 ABI 寄存器**。走 `DPL/DPH/B/A` 的话，站点要付两次
逐字节往返（入 4 条 + 出 4 条 `mov direct,direct`，各 3 B，共 24 B），比模板本体
还贵。`@Ri` 能寻 8 位 IDATA，而 DSEG 槽就在 0x30–0x7F，于是站点只剩 7 B。

## 3. 效果

`i32 >> 3` 的整份固件（`bincompare.py` 口径，含同一个空壳 harness）：

| 实现 | 总 BIN | 相对空壳 Δ |
|---|---:|---:|
| 改之前（内联 → 被 factor 提取） | 152 B | 131 B |
| 寄存器版模板（中途方案） | 114 B | 93 B |
| **现方案（@r1 直连槽）** | **84 B** | **63 B** |
| Keil C51 | 60 B | 33 B |
| SDCC 4.6 | 232 B | 46 B |

比改之前省 **68 B（−45%）**。

还有 24 B 的差距，全部来自静态槽 ABI：参数进来要 12 B（4 条 `mov direct,direct`
落到 `_mcs_vN`），结果出去再 12 B。Keil 用寄存器传参，这两笔它不付。这不是模板
能解决的，属于「站点 ABI 搬运」那条老账。

## 4. 三条硬约束

### 4.1 只用 r0–r4

`assignRegisters` 固定分配 R5/R6/R7。模板避开这三个，就不必给寄存器分配加
「某函数禁用某几个寄存器」的特殊规则。当前 `sar32` 只占 r0（次数）和 r1（指针）。

### 4.2 ISR 内不套模板

中断现场只保存 A/PSW/DPTR/B。主程序正在模板里跑时被 ISR 打断，而 ISR 里如果也
调模板，会把 r0/r1 踩掉。用 `is_isr` 把关，退回内联——与 `assignRegisters`
对 ISR 的处理同源（ISR 一律不碰 rN）。

### 4.3 模板原地改槽，必须确认 lhs 已死

模板把结果写回输入槽。只有在「lhs 此后不再被读」时才能原地，否则先复制一份
到新槽（12 B）。判定用两条：

```
reuseWideDst(body, idx, lhs, a, 4)          // 存储别名 + 紧接着 store 回同槽
airLastRead(lhs) <= @backingInt(inst)       // 当前指令是最后使用者
```

`airLastRead` 返回「最后一个使用它的 AIR 编号」，**当前指令自身也算使用者**，
所以要 `<=` 而不是 `<`（写成 `<` 时判定恒为假，函数里会多出一次 12 B 复制）。

## 5. 符号是汇编单元局部的

模板文本不加 `.globl`：多个编译单元各自带一份自己的副本。代价是每单元多
20 余字节，换来「链接时不会撞符号」。

`rtlib.take(id)` 做单元内去重：第一个用到的函数负责把文本带出去（追加在该函数
体之后），同单元后续函数只发 `lcall`。

## 6. 与 factor 的分工

| | rtlib | factor |
|---|---|---|
| 管什么 | **标准算子**（移位、乘除） | 用户自己的重复算法块 |
| 识别方式 | AIR 层按 tag + 类型匹配 | MIR 层按块指纹统计 |
| 代码来源 | 手写汇编 | 后端生成的块体 |
| 可重入 | **是**（纯函数，无静态状态） | 否（复用拥有者的槽） |
| ISR | 不参与 | 不参与 |

rtlib 比 factor 更强的一点是可重入。factor 的共享例程复用的是拥有者函数的静态槽，
「拥有者执行中调别的函数、那个函数又用同一例程」会踩；rtlib 只用寄存器和传进来的
槽指针，没有这个问题。

## 7. 安全特性的影响

**`sar32` 这条完全不影响**——移位不产生溢出，Zig 的 AIR 里也没有 `shl_safe` /
`sar_safe` 变体，`ReleaseSafe` 与 `ReleaseSmall` 发同一份模板。

乘除模板化时要额外注意两件事（还没做，先记在这里）：

1. **模板要分两版**：`_mcs_rt_<op>`（无检查）与 `_mcs_rt_<op>_safe`（带检查 +
   跳全局 `_mcs_panic`），按 `-OReleaseSafe` 选，与 `add`/`add_safe` 的分裂同构。
2. **顺带补两个现有缺口**：
   - `mul_safe` 的多字节/有符号分支现在是**编译期拒绝**（`mcs2.zig` 里
     "ReleaseSafe 的多字节/有符号乘法溢出检查尚未实现"），模板里正好能实现；
   - `divmodWide()` 里**没有任何除零检查**（`panicTarget`/`jz`/`zero` 命中 0 次），
     除零会一路算下去给出错误结果而不停机。模板里加 4 条指令即可补上。

## 8. 验收门禁

- `sar32`：`want_rt=1`——产物里必须有 `lcall _mcs_rt_`，且模板文本
  （`\n_mcs_rt_sar32:`）**恰好出现一次**。重复定义会让链接直接失败，退化成
  内联则白丢 68 B。
- `sar32v`（`examples/mcs51/src/rtvar.zig`）：`want_no_rt=True`——运行期移位次数
  必须保持内联。`djnz` 是先减后判，次数 0 会转 256 次；这条断言把「常量才走模板」
  钉住。反例单独一个文件，否则同单元里 `sar32` 的 `lcall` 会让断言误判。
- 结果正确性由 `want32` 保证：`sar32` = `0xFFFFFFFE`，`sar32v` = `0xFFF95FD7`。

### 8.1 值域扫描（`rtcheck.py`）

上面每条用例只测**一个**值。模板是手写汇编，单个值远不足以说明语义正确——
算术右移最容易错的两处（每轮重设符号位、`rrc` 链把上一字节的 bit0 当进位）
只在特定值上才暴露。所以另设 `tools/mcs2/rtcheck.py` 做值域扫描：

```
python rtcheck.py          # 默认 sar32
```

它用**真实编译产物**（不是手写探针）在 ucsim 上跑 10 组边界值：

| 值 | 次数 | 想钉住的点 |
|---|---:|---|
| `0x12345678` | 3 | 常规正数 |
| `0xFFFFFFFF` | 3 | 全 1 负数 |
| `0xFFFFFFF0` | 3 | 与 `mcs2.py check` 同一个值，可交叉核对 |
| `0x80000000` | 1 | 符号位刚置位——错成逻辑右移会得 `0x40000000` |
| `0x7FFFFFFF` | 1 | 符号位为 0 的最大正数 |
| `0xCAFEBABE` | 11 | 次数跨字节 |
| `0x00000000` | 5 | 零 |
| `0x80000001` | 31 | 次数上限 + 负数 |
| `0xFFFFFFFF` | 31 | 次数上限 + 全 1 |
| `0x0000FFFF` | 15 | 低位全 1，移到最后只剩 1 |

现行结果 **10/10 通过**，`ReleaseSmall` 与 `ReleaseSafe` 两档产物一致
（`sar` 无溢出检查需求，两档发同一份模板）。

分工：`mcs2.py check` 是每次必跑的门禁（快，1 个值）；
`rtcheck.py` 是改模板后手工跑的值域扫描（慢，10 个值）。加新模板时，
在 `report()` 里挂一组用例即可。

### 8.2 真机验证（AI8051U）

**结论：129 项全部通过**，含走 rtlib 模板的 `sar32`。

环境：AI8051U 核心板，COM14，AiCube-ISP v6.97C，40 MHz @ 115200
（Timer2 重载 `0xFFA9`），`realcheck.py --auto COM14`。

```
PASS sar32 = 0xFFFFFFFE（期望 0xFFFFFFFE）
PASS sar8  = 0xFC（期望 0xFC）
...
== 收齐 129/129
```

`sar32` 这一条在真机上覆盖了三件 ucsim 模拟不到的事：

1. `@r1` 间接寻址访问 DSEG 静态槽（`mov a,@r1` / `mov @r1,a` 的真实时序）
2. `djnz` 循环在真实指令周期下的计数衰减
3. `rrc` 链跨 4 字节的进位传播（符号位保留全靠它）

这三处都是模板最容易踩硬件差异的地方，仿真过了不等于真机过。

**首次全量 125/129**，缺的 4 项是 `symtab.zig` 那一组，一条数据都没收到
（不是值错，是完全没输出）。补跑一次即全过——那是**烧录没成功**，不是
代码问题：`--flash-wait` 给了 12 s，AiCube 那次没在窗口内完成检测+下载。
**建议默认给 16 s。**

### 8.3 实机链路的三个坑（都已修）

**① AiCube 监视的是它界面底部那个路径框里的文件，不是固定文件名。**
`--auto` 原来默认写 `build/fw/real_live_ai8051u_115200.ihx`，而 AiCube 实际
装载的是 `build/fw/realapp_ai8051u.ihx`，写前者的结果是**静默不烧**：串口
收不到数据，看起来像固件有问题，白查一轮。

新增 `tools/mcs2/aicube.py`，用 `WM_GETTEXT` **只读**地把路径与串口号问出来
（不点按钮、不改勾选项——盲点坐标曾把别人的「下次用 HID 接口下载」勾错）。
`realcheck.py` 的 `--live` 改为默认 None，自动取这个值，读不到才退回旧默认。

```python
import aicube
aicube.probe()      # {'port': 'COM14', 'ihx': 'E:\\code\\yuyan\\build\\fw\\realapp_ai8051u.ihx'}
```

**② 同一源文件在 `fw/` 里会有多份历史固件，按文件名排序会选错。**
组号随用例表增删而平移，旧的 `real_g12_sar_*.ihx` 不会自动删。原来
`cands[-1]` 用字符串排序，`real_g9_` 会排在 `real_g12_` 之后（`'9' > '1'`），
挑到旧的那份。旧的若不带 `--isp`（没有 `mov 0xC7,#0x60`），烧上去之后芯片
**就不能再自动进 ISP**，后面每组都要断电重来——症状是「前几组正常，跑一半
突然全失败」。改为按 `st_mtime` 取最新。

**③ 芯片在跑用户程序时不会自己进 ISP。**
CH340 板没有自动下载电路，靠固件里的 `isp_watch`（收到串口字节 → `IAP_CONTR=0x60`
软复位进 ISP）+ AiCube 的「下载前先发自定义命令 `@STCISP#`」。所以
`realcheck.py --build --isp` 是**必须**的：不带 `--isp` 的固件烧上去，
下一次就得人工断电。

## 9. 下一步

1. `shr32` / `shl32`：同一个机制，模板各 20 余字节，站点同样 7 B。
2. `u32` 乘除：最亏的 `i32div`（Δ 314 B）在这里，但要一并建 `_mcs_panic` 与
   safe/small 双版本（见 §7）。
3. 参数直通：`.arg` 现在无脑落槽，4 字节参数就是 12 B。若能识别「只被这一处用」，
   站点还能再省 12 B，`sar32` 有望压到 72 B。

## 10. 排除的两个方案

- **寄存器版（DPL/DPH/B/A 传参）**：先做过一版，站点 24 B 往返把收益吃掉一半，
  实测 114 B。拒绝。
- **`mov rN,#符号`**：sdas8051 不接受（Invalid Addressing Mode），必须写
  `#<(_mcs_vK)` 取低字节。
