## 0. 一句话现状

8051 后端（mcs2）已能编：**u8/u16/u32/i8/i16/i32 的加减、乘、除、取余、移位（常量与运行期次数）、
比较（含跨 4 字节借位链）、按位与或异或取反、符号扩展、bool 返回**，加位测试、中断、环形缓冲，
以及**内部调用 / 间接调用（函数指针）/ 固定地址多字节读写 / 多字节元素带下标（scale=1/2/4，相邻两元素）/
全局数组的符号基址（`table[i]`）/ 函数指针表（`@intFromPtr` + `@ptrFromInt` 间接调用）/
**`const` 常量表（初值进代码段 `.db`，`movc` 读——CRC 表/字模/字符串这类查表终于能用）/**
**真 `switch`（多 case / 范围 / else / enum）+ `if`/`switch` 表达式（内存 phi）**；
还有 **CORDIC 定点数学库** `tools/mcs2/lib/cordic.zig`（`sin`/`cos`/`atan2`/`sqrt32`/`hypot`/`mulQ14`，
纯加减+算术右移、Q14 输出、二进制角，无浮点）；
验收 **133 项仿真全过**（2026-11-01 晚）；**真机套件 129 项 / 42 组**（含尾递归、运行期指针、3D 数组、宽全局、B 保护、**Timer0 中断**）；**硅片实测全过**（8 位模式、UART1 P3.0/P3.1、Timer2 40MHz@115200）——
**2026-11-01 起真机套件全自动**：25 组固件由 `realcheck.py --auto` 逐组写文件 → AiCube 自动发
`@STCISP#` → 固件自己复位进 ISP → 烧录 → 收数，**全程不用碰板子**（见 §7.1.1）。
之前唯一没采到的 `setbit` 也补上了（把实验对象从 SCON 换到位可寻址 RAM 0x20，见坑 22）；
**浮点不做**：按用户决定，浮点一律用 **STC 官方浮点库**（C 侧链接），后端只保证定点。
另外还上硅跑了一个**真程序形状**的固件 `realapp`（函数指针表分派 + u16 乘法 + UART 打印，见 §7.2），
它当场抓出一个真 bug：**调用会踩 DPL**，导致「算一位、发一位」的写法第二位用错参数（已修，见坑 21）；
尺寸 `sum` 19 B（优于 SDCC 20 B）、`ringdemo` 78 B（Keil 60）；
**内部调用（M2.5）已通**：内部 ABI 与 SDCC 边界 ABI 一致，双向混编（C↔Zig）实跑通过；
**未做**：switch（跳转表）、多字节全局变量/指针间接读写、if 表达式（块返回值）、饱和算术、
16×16→32 专用乘法、递归（静态 PARM 区不支持）。

> **决策（2026-11-02）**：**8051 的 bit 空间只用于 SFR 单字节位操作**（`setb P1.1` 这类）；
> **bool / u1 一律按 1 字节存、用「与/或/非 + 截取」表达**，不做 `u1 → bit` 的表示转换。
> 理由：bit 只能落在 BSEG/SFR 位、地址必须编译期定，而槽址是后期复用才定的；
> 且 `i1` 真值是 −1，混进来更贵。收益走「比较结果只用于分支时不落字节」这条路。

## 4. 坑清单（都踩过，别再踩）

1. **DPL 既是 arg0 又是 DPTR 低字节**：用 dptr 的函数先把 arg0 搬进 vreg（`needs_dptr`）。
2. **DPH 是 DPTR 高位**：测试驱动读 u16/u32 返回时，必须先 push DPL/DPH/B/A 再建指针。
3. **Zig 并行编译函数**：vreg/标签/临时标签是全局计数器 → 必须串行化（已加自旋锁）。
4. **sdas8051 只认 `cjne a,...`**：`cjne 直址,#imm,rel` 报 Invalid Addressing Mode。
5. **SFR 位地址 = SFR 地址 + 位号**（且 SFR 必须 8 字节对齐）：`SCON.1`=0x99，不是 0xC1。
6. **u1/u64/i8 曾被静默当 1 字节**：现在有 `requireIntWidth` 闸门，只认 u8/u16/u32。
7. **ISR 必须 pop+reti**：`Lower.is_isr` 漏赋值会让 ISR 以 `ret` 结束（栈错乱）。
8. **参数符号名要逐个释放**：否则 SafeAllocator 报 leak。
9. **非 2 的幂位宽作 export fn 参数是 Zig 前端拒绝**（不是后端问题）。
10. **摆参数必须先快照所有实参**：实参可能还在 DPL/DPH/B/A 里，边摆边取会把后面的踩掉
    （`chain32` 就是 0x12345621 变成 0x12345256）。
11. **读返回值要「从高字节往低读」**：读 ACC 用的是 `mov a,0xE0`，而 ACC 就是 A 本身——
    先读 DPL/DPH/B 会把 A 踩掉，于是第 4 字节读成 B 的值（实测 0x12 读成 0x34）。
12. **8051 的 RET 先弹高字节**：自己搭返回地址时每个 16 位值必须「先压低、后压高」
    （高字节在栈顶）。顺序反了会跳到 0x0D00 之类的地方——`call_ind` 就是这样返回 0xBD 的。
13. **间接调用的标签要跨函数唯一**：同一个 .asm 里两个函数各自造 `L0` 会重定义
    （用模块级序列 + 高位前缀）。
14. **函数地址必须 export 目标函数**：没人直接调它 → 后端当死代码丢掉 → 地址悬空、链接报未定义。
15. **MIR op 加字段要改「所有重建点」**：`load_xdata_idx`/`store_xdata_idx` 的 `scale` 在
    `mcs51.zig` 的 vreg 重定基和 `mcs2.zig` 的 `substReadVreg` 里各丢过一次（默认 1）——
    单元素用例自己写自己读，地址一致所以「全过」；相邻两元素才暴露（`t16pair` 高字节被邻元素 low 覆盖）。
16. **ucsim 的 `step N` 到点就停，不足的步数会伪装成「高字节算错」**：scale=4 的相邻元素用例约 700 步，
    默认 400 步截断后读回 `0xBD7535BD` 这类垃圾。多字节表用例按「xdata 访问次数 × ~30 条」估步数。
17. **一个验收源塞 6 个函数会超 DSEG**：每函数一块静态槽，6 个（含两个 u32 表用例）要 96 B，
    而 0x30–0x7F 只有 80 B → `sdld: Could not get 96 consecutive bytes`。按 3–4 个函数拆文件
    （`tableidx.zig` 46 B / `tableu32.zig` 50 B）。
18. **全局变量与函数的汇编符号命名不一样**：变量是 `_<未限定名>`（`_tbl`），函数是 `_<fqn>`（`_fptab_f_inc`）
    再加一个 `_<导出名>` 的 `ljmp` 别名。按统一规则拼名字会链不上（`undefined symbol`）——
    大小写/前缀错一点都不报在代码里，只在链接期出现。
19. **`@intFromPtr(&f)` 的结果是 usize（本目标 24 位）**：直接当 `u16` 返回是「前端拒绝」不是后端问题，
    必须 `@truncate` 到 16 位再用。
20. **`var` 的初值不会被装载**：`var t: [4]u16 = .{…}` 只占 XSEG 空间（`.ds`），内容是随机的 ——
    8051 的 RAM 掉电即失，本来也没人去装载它。**查表请用 `const`**（M2.6d：进代码段发 `.db`，`movc` 读），
    `var` 表就当「缓冲区」，运行时自己填。
21. **调用会踩 DPL/DPH**：1 字节 arg0 平时是「就地当 DPL」用的（省一次 mov），而 `lcall` 会把被调方的
    arg0 放进 DPL、arg2 放进 B。本函数若在调用之后再用参数，读到的就是**上一次的实参**。
    修法：`airNeedsDptr` 把 `.call*` 也算成「会写 DPL」，先把 arg0 搬进槽。
    典型翻车：`puthex` 里「算一位、发一位」（`realapp` 就这样打出 `0 44` 而不是 `0 45`）。
22. **RAM 的位地址 ≠ SFR 的位地址公式**：SFR（≥0x80）是「地址 + 位号」（0x98.1 → 0x99）；
    **0x20–0x2F 的 RAM 是「位号连续跨字节」**：(地址−0x20)×8 + 位号（0x20.1 → **0x01**）。
    拿 SFR 公式套 RAM 会指到别的字节（0x21 其实是 0x24.1），于是 `setb` 置错位、读回还是 0。
    顺带：以前 `sfrBitAddr` 只认 SFR，对 0x20–0x2F 做 `|= 单比特` 只能发 `orl dir,#imm`（多 1 字节）。
23. **相邻拷贝折叠不能拿 ABI/易失寄存器当源**：`mov v4,0x82`（把 DPL 拷进槽）后紧接一条会**先写 DPTR**
    的指令（`mov dptr,#_sym`），折叠会把读 `v4` 换成读 `0x82` —— 读到的是新 DPL。
    症状：`const tbl` 的 `tbl[i]` 恒返回 0xFF（读飞了）。`foldCopies` 现在跳过源为 0x82/0x83/0xE0/0xF0 的折叠。
24. **`.alloc` 的指令类型是 `*T`，不是 `T`**：直接把它喂给 `storageBytes` 会因「非 int」返回 **1**，
    于是 `var x: u16` 只分到 1 个槽，之后 2 字节的 store 把**下一个局部量**踩掉。
    症状：一个函数里连着三个 i16 局部量时，CORDIC 的 `sin` 恒返回 0（z 的高字节被 x 的 low 覆盖）。
    修法：`.alloc` 先 `childType` 再算宽度。**宽局部量必须单测**（`wloc1/wloc2`）。
25. **`if (a != 0 or b != 0)` 不允许**：bool 的 `or` 会走一条后端未实现的 AIR 形态（报「M1 不支持该编译期引用形态」），
    写成嵌套 `if` / `if … else if` 即可。库代码里踩过一次（`atan2`）。

27. **`sqrt32`/`hypot` 返回 0：一个临时标签在同函数里被定义两遍**（2026-11-01 未修完）。
    现象：`cordic_sqrt.zig` 能链（DSEG 79 B），但真机/仿真结果都是 0；合并后的 .asm 里
    `L2147483654:` 出现两次——第一处紧跟在一个 `ret` 之后（死区），而 `jnz` 恰好跳向第一处。
    已排除：前后端 ops 流里**没有**重复 `.label`（在 lowering 每个 pass 后都自查过），
    各函数的 `label_base` 互不重叠（chyp=0 / absU=6 / hypot=30 / csqrt1m=50 / sqrt32=56）。
    所以重复是在**渲染/松弛阶段之后**才出现的，下一步从 `mcs51.zig` 的 `relaxJumps`（条件跳转越界展开时
    会 `max_label += 1` 造新标签）和 `compactJumpToNext` 两处查。
    已加保险：`rotateDjnz` 前后快照比对，发现重复标签就整段回退（不会发坏代码）。
26. **真机收集器靠「打印标签 = 用例名」匹配**：固件里打 `isr=`、用例名却是 `interrupt`，
    收集器一律判「缺 interrupt」，表现得**和固件挂死一模一样**（串口上明明在出数）。
    怀疑「芯片锁死/固件静默」之前，先用原始串口 dump 看一眼 —— `_raw.py`/`--watch` 别只看汇总。
27. **真机用例里不许放「等外部状态」的死循环**：`bitpoll` 轮询一个位，硅片上那位不变就永远出不来；
    而自动烧录的 ISP 触发代码在打印循环里 → 固件一挂，`@STCISP#` 再也没人接，**整轮自动烧录被卡住**
    （2026-11-01 踩过：从 `bit` 组开始后面 15 项全丢）。两条对策都已落地：
    ① `bitpoll/bitclear` 不进真机套件；② 固件加 **UART1 接收中断**版触发（向量 `0x0023`，
    ISR 里写 `IAP_CONTR=0x60`），主循环挂死也能被下载命令救回来。

### 7.1 AiCube 自动烧录的**真实工作方式**（2026-11-01 实测定版）

1. AiCube 监控的是它**当前装载的那个文件**（界面底部路径框里那个），不是固定文件名。
   所以把固件写到 `build/fw/real_live_*.ihx` 没用；要写到**它装载的路径**上，
   例如 `realcheck.py --auto <COMx> --live build/fw/<它装载的文件>`。
2. 文件一变 → AiCube 自动装载并发下载命令（左下两个勾要亮着）。
3. **ISP 握手是唯一的坎**，但只要打开「自定义指令自动下载」（§7.1.1）就完全免人工：
   工具先发 `@STCISP#`，固件自己写 `IAP_CONTR=0x60` 复位进 ISP，工具接着烧。
   不打开那项时，芯片在跑用户程序就进不了 ISP，AiCube 会停在「正在检测目标单片机」，
   只能**按复位/拔插 USB**（本机 CH340 板没有自动下载电路）。

**实测（10:09）**：改一行固件 → `python mcs2.py fw realapp` 覆盖到 AiCube 装载的路径 →
十几秒后串口变成新固件的输出（`0v2 45` 里的版本号变了），**全程没碰板子**。
所以真机套件可以整轮自动跑：

```bash
    --per-group 8 --flash-wait 9                # 逐组写文件 → 自动烧 → 收数比对
```

### 7.1.1 「自定义指令自动下载」——免拔插 USB 的正路

AiCube 里有一块面板（在「下载口令」同一个区域），内容长这样：

```
下载口令   收到用户命令后复位到ISP监控程序区
○ USB-CDC/串口模式   ● USB (HID) 模式
自定义命令  @STCISP#   □ Hex
□ 使用默认的内部自定义命令 "@STCISP#"
□ 下次使用HID接口进行ISP下载
□ 每次下载前都先发送自定义命令
[ 发送用户自定义命令并开始下载 ]
```

机制：**下载前先按用户波特率发一串自定义指令**，跑在芯片里的固件认到就把
`IAP_CONTR = 0x60`（SWBS|SWRST）写进去 → 复位进 ISP → 工具接着握手烧录，**不用拔插 USB**。

固件侧我们已经有了两种等价实现：

- 微用例外壳：`realcheck.py --isp`（`ISP_WATCH`，串口收到**任何**字节就复位，不认魔法字——
  因为下载波特率可能与用户波特率不同，收到的其实是乱码）；
- 真程序形状：`tests/realapp.zig` 的 `isp_watch()`（同样逻辑，`main` 循环里每轮查一次 RI）。

⚠️ 注意两点：

1. 这三个勾在「USB (HID) 模式」下是**灰的**，要先选「USB-CDC/串口模式」；
2. **同一个面板里就是「下载口令」**——那两个框千万别填（设了就是一次性锁，连错 5 次砖）。
> 实测：**上一次下载干净结束后，下一组的自动装载+下载往往不用复位就能成功**；
> 一旦某次卡住，之后必须人工复位一次才能继续（别反复点，白等）。

> 收数也可以单独做：`python realcheck.py --watch <COMx> --seconds 10`（固件是循环打印的）。

## 7.2 `realapp.zig`：写「像真程序的固件」时撞到的三件事

`python mcs2.py fw realapp` → `build/fw/realapp_ai8051u.ihx`（1436 B）：
main 里建**函数指针表**（3 个命令处理函数 `u8→u8`，其中一个内部还做 u16 乘法）、
按表分派、经 UART1（P3.0/P3.1 + Timer2 @40MHz/115200）打印 `0 xx` 循环。
这是「真代码形状」的固件，不是微用例；写它的过程中撞到：

1. ~~`HEX[i]`（const 数组运行期下标）走 AIR `array_elem_val`，mcs2 没实现~~ → **已支持**（M2.6d：
   常量表进代码段 + `movc`），当时是先绕成算术算十六进制数字。
2. **`if` 表达式不支持**（块返回值），`return if (a) x else y;` 要改写成 `var` + `if` 语句。
3. **inline 会把 DSEG 算到调用者头上**：一开始 `putc/puthex/hexdigit` 全 inline，`main` 一个函数就 122 槽；
   把 `putc`/`putbyte` 改成普通函数后总槽数降到 **59**（≤80 才链得上）。这条是「真程序」里最容易踩的尺寸坑。

> 顺带修了一个**真 bug**：内部调用路径每次 `mangleNavSymbol` 都漏一份符号串（SafeAllocator 会报
> `error(SafeAllocator): leaked`，但 zig 仍以 0 退出，所以之前的验收没暴露）。现在调用符号进 `sym_pool`，
> 与数据符号一起在 `generate` 末尾释放。
