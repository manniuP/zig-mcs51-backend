# 05 移植到 MCS-251

## 1. 为什么要 251

STC AI8051U 是 **MCS-251（80251）** 核，兼容经典 8051 指令。用 251 模式可以：

- 使用 `DR`（双 DPTR）、`ECALL`/`ERET` 等 251 指令；
- 指针为 24 位（3 字节），可寻址大空间，标量为**大端**。

本机 SDCC 只带 `sdas8051`，**没有** `sdas251` 和支持 mcs251 的 `sdld`，
所以默认示例走 8051 兼容模式。要真正上 251，需要先构建 `sdcc-c251`。

## 2. 构建 sdcc-c251 工具链

参考 [08-驱动与链接详解](08-驱动与链接详解.md) 第 5 节与 `tools/wsl_build_sdcc.sh`：

1. 在 WSL 里进入 `sdcc-c251/`，执行 `configure`（启用 mcs251 端口，例如
   `--enable-mcs251-port`）；
2. `make`，得到支持 251 的 `sdas251.exe` / `sdld.exe` 及 `mcs251-*` 运行库；
3. 把可执行文件与库目录路径记下来，供构建脚本使用。

## 3. 251 目标的差异一览

| 项 | 值 |
| --- | --- |
| Zig target | `mcs251-freestanding` |
| SDCC 目标 | `-mmcs51` → 改为 `-mmcs251` |
| 汇编器 | `sdas251` |
| 链接 | `sdld -r -nf <lk>`（多一个 `liblonglong`） |
| 返回指令 | `eret` |
| 指针 | 24 位（3 字节，高字节在前） |
| 标量字节序 | 大端 |
| 启动库 | `mcs251`（而非 `mcs51`） |
| 库顺序 | `mcs251`、`libsdcc`、`libint`、`liblong`、`liblonglong`、`libfloat` |

互操作约定：所有编译单元统一使用 `--stack-auto` / `__reentrant`，ABI 采用
`sdcc-c251/doc/mcs251/abi.md` 的 **revision 2**。

## 4. 切换示例工程

以 `examples/ai8051u_blink/` 为例，把 `build.ps1` 中：

- C 的 `-mmcs51` 改为 `-mmcs251`；
- Zig 的 `-target mcs51-freestanding` 改为 `mcs251-freestanding`；
- `sdas8051` 改为 `sdas251`；
- 链接仍调用 `sdcc`（分支版），并确保其库目录指向 `mcs251` 系列。

> 注意：8051 与 251 的**标量字节序相反**（小端 vs 大端）。若 C 与 Zig 之间
> 传多字节标量，升级目标后要重新核对字节顺序。单字节接口不受影响。

## 5. Zig 后端在 251 上更完整

自举后端对 MCS-251 的支持范围大于 MCS-51，例如：

- 切片（`.array_to_slice`/`.slice`/…）与运行期下标；
- 变参（`@cVaStart`/`@cVaArg`/…）；
- 间接调用（3 字节函数指针经 `DR28` + `ecall @dr28`）；
- 24 位地址算术、`DR` 双 DPTR。

MCS-51 下这些会给出明确的编译错误。因此复杂逻辑更适合放到 251 目标。
