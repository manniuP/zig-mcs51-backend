> 哪些大件/产物可清理、哪些**不能删**，以及恢复方法。

| 项目 | 大小 | 说明 | 如何恢复 |

| `driver/` | 小 | 旧构建脚本 `build.ps1` 与参考 `crt0-*.asm`；已被 `xmake.lua` 取代。`crt0` 参考已移入 `lib/crt0/` | `git checkout` 历史版本 |

| 各示例构建产物 | <数 MB | `*.asm/*.rel/*.ihx/*.lst/*.rst/*.sym/*.map/*.mem/*.lk/*.dumpcustom*` | `xmake build <目标>` 重新生成 |

## 二、明确保留（不要删）

| 项目 | 原因 |
| --- | --- |
| `compiler/`（源码 + `lib/`） | MCS 后端编译器源码；`compiler/lib` 是 `ZIG_LIB_DIR` 需要的 std（含 mcs51/mcs251 目标定义）；源码被 git 跟踪，可 `git checkout` 恢复 |
| `compiler/zig-out/bin/zig.exe` | 由源码用系统 zig 重建的编译器（工具链核心） |
| `compiler/zig-out/bin/zig.pdb`（若有） | 该编译器的调试符号，排障时符号化栈回溯用 |
| `tools/sdcc-mcs251-windows-x64/` | 预编译 SDCC 4.6.0 mcs251 工具链（`sdcc`/`sdas251`/`sdld`），必需（**不入库**，需按下方恢复） |
| `tools/vendor/stc/` | ~1.6 MB，`tools/keil2sdcc*.py` 重生成 SFR 头时要用 |
| `lib/`、`examples/`、`docs/` | 源码与文档 |

## 三、恢复方法

```powershell
# 1) 预编译 SDCC mcs251 工具链（若被清）
#    见工作区 docs/ 的“可清理与重新下载清单”，或用 WSL 重编 sdcc-c251
#    （source: https://github.com/zevorn/sdcc-c251，或 tools/wsl_build_sdcc.sh）

# 2) 重编编译器（自举前请先经用户确认）
cd <workspace>\mcs251\compiler
zig build -Doptimize=ReleaseFast -Dno-lib --zig-lib-dir <workspace>\mcs251\compiler\lib
# -> compiler\zig-out\bin\zig.exe

# 3) 构建示例
cd <workspace>\mcs251
xmake f --mcs_arch=mcs251
xmake build ziglog
```

## 四、git 可恢复 vs 需重新获取

- **被 git 跟踪**的（`compiler/`、`lib/`、`examples/` 源码、`docs/`）：误删可
  `git checkout -- <path>` 恢复，不必下载。
- **未跟踪且被 `.gitignore` 忽略**的（`tools/sdcc-mcs251-windows-x64/`、
  `tools/vendor/`、`compiler/.zig-cache*/`、各示例产物）：删了需按本页方法重新获取/重建。
