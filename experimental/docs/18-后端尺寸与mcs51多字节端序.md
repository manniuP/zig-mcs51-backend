# 18 - 后端尺寸优化（A2/A3）与 MCS-51 多字节端序修复

> 承接 [17-后端IR提示与中间层优化](17-后端IR提示与中间层优化.md)（`mcs_ir` 值级优化）。
> 本轮：后端小项 **A2**、条件融合扩展 **A3**、8 位 **C1**（测试 + 端序修复）、clangd **D1**；
> 热函数自动内联 **B1** 评估后暂缓。

## A2：帧指针调整直接发 `add/sub spx,#imm16`

- `CodeGen.appendAdjust` 原先发 `inc/dec spx,#4` 序列，靠构建层 `mcs_opt.py` R1 合并。
- 现后端直接发：`amount ∈ {1,2,4}` → 单条 `inc/dec spx[,#imm]`；**其余** → 单条 `add/sub spx,#imm16`
  （超 `0xFFFF` 分块）。调用点由 `.inc/.dec` 改为 `.add/.sub`。
- **尺寸依据**（`forms.zig`）：`inc wr4,#2` 源 2 字节；`add wr4,#0x1234` 源 4 字节。
  故小量用 `inc/dec` 更短，大量用一条 `add/sub` 优于拆多条。
- 效果：默认管线最终 CSEG 与旧**一致**（R1 本就会把 `inc` 序列合成 `add`），但**不再依赖 R1**、
  中间 asm 更小；直接只跑编译器（不经 `mcs_opt`）时输出也已经紧凑。
- 实测：`zigmem` 默认 1191 字节（不变）；prologue `add spx,#0x0008`、单帧 4 字仍 `inc spx,#0x04`。

## A3：条件融合扩展（`-OReleaseSmall`）

- `isFusableCmpTag` 增加 `.not` / `.bool_and` / `.bool_or`；`planFusion` 对 `.not` 选 `jz`
  （`jump_if_true=false`）。新增 `emitFusedCondToA`：
  - `cmp_*` → `emitCmpToA`（同前）；
  - `.not` → 把操作数算进 A，配合 `jz`（A==0 即 `!x` 为真）；
  - `.bool_and`/`.bool_or` → A 做 `anl`/`orl`，`jnz` 直接测 A（MCS-251 的 `jz/jnz` 测 A）。
- 目的：免去把 bool 物化 0/1 存帧再读回。
- 验证：临时用例 `const c = (i==1); if (!c) ...`（`-OReleaseSmall`）→ QEMU 输出 `02` 正确；
  `-ODebug` 不受影响（融合仅在 `aggressive_size` 开启时生效）。
- 注意：用户写的 `and`/`or` 会被前端**短路**成控制流，很少生成 `.bool_and/.bool_or`；本扩展主要
  覆盖 `.not` 与内部产生的 bool_and/or，正确且无害。

## C1：mcs51 扩展测试 + 多字节端序修复（重要）

- 扩展 `examples/at89c52_sim`：`led.zig::mix_test()`（u16 加/移位 + 全局 u8/u16 读写 + `@truncate` + 异或），
  `main.c` 加检查（failcode `0x60`）。
- **发现并修复共享 bug（影响 mcs51）**：内存→帧的多字节读一律写成 `frameOperand(dst + j)`（按**内存序**），
  但：
  - 内存是**大端**（`derefSymbolWrite` 用逻辑字节 `size-1-m`，与 SDCC/C 一致）；
  - 帧端序**按架构不同**：MCS-251 帧为**大端**、MCS-51 帧为**小端**（`slotByte`）。
  - 于是 mcs251 恰好正确，而 **mcs51 读多字节全局会字节颠倒**：`gy=0x1234` 后 `@truncate(gy)`
    取到 `0x12` 而非 `0x34` → `mix_test` 出错、`failcode=0x60`。
- 修复：新增 `memByteDisp(disp, j, size) = slotByte(disp, size-1-j, size)`，并替换所有内存→帧读：
  `derefSymbolRead`、`derefFixedRead`、`derefReadRi`、`derefReadDptr`、`derefRead`(xdata 24 位)，
  以及 slice/变参的内存读。**对 mcs251 是恒等变换**（`slotByte` 两次取反抵消），故 mcs251 零回归。
- 验证：ucsim `simtest` 从 `55 60`（失败）→ `aa 00 02 04 08 10 20 40`（全过）；
  mcs251 各例（`zigmem`/`zigslice`/`zigns`/`zigrtindex`/`zighotcold`）QEMU 输出不变；CI 全绿。

## C3：运行期 / 全局切片值（切片小尾巴）

- 之前只支持**编译期切片**（`const s: []const u8 = &arr;`，没有对应 AIR 指令）；而
  `var/const s: []u8 = &buf;` 这类**运行期切片值**（`{ptr, len}` 需物化）会报
  `mcs backend: cannot materialize constant aggregate value`，运行期下标的 `s[i]`/`&s[i]` 也随之不可用。
- 修复三处（`compiler/src/codegen/mcs/CodeGen.zig`）：
  1. `emitStore`：常量切片的 rhs 走 `comptimeSliceOrigin` 物化（`ptr` + `len` 写帧，并记 `slice_origin`），
     不再交给 `emitConstAggregateStore`（后者无法序列化含符号的切片）；
  2. `sliceView`：对**内嵌的编译期切片常量**（interned ref）也返回 `comptimeSliceOrigin` 的视图；
  3. 新增 `materializeSliceAddr`：切片元素地址在「运行期帧基址」与「编译期全局/固定基址」两种来源下
     都能物化（全局经 `#sym` 装入 `@dr28` 再加常量偏移），`emitSliceAddrDispatch` 改用之。
- 覆盖：切片构造、`s.len`、运行期下标读 / 写 `s[i]`、`&s[i]`、切片逐项拷贝到另一全局数组。
- 新增示例 `examples/ai8051u_zig_rtslice/`（`xmake build zigrtslice`）：QEMU 输出
  `40 41 42 43 44 45` / `s[3]=43` / `42434445` 正确；CI 目标表已加入 `zigrtslice`。
- **真机（AI8051U-34K64）通过（2026-09-16）**：烧 `rtslice.ihx`，串口 9600 输出同 QEMU：
  `40 41 42 43 44 45` / `s[3]=43` / `42434445`。（同版编译器含 A2/A3/C1/C3。）

## B1（热函数自动内联）——评估后暂缓

- 实现需改**前端**（`Sema` 的 `inline_requested`）把 `linksection(".hot")` 函数当 `inline`；
  影响面大（递归/复杂控制流不能内联会报错、错误路径、跨后端），且内联通常**增大体积**
  （后端本就按内联点复制代码，见 [15](15-汇编瘦身工具mcs_opt.md)/[17](17-后端IR提示与中间层优化.md)），
  与当前**尺寸**目标相反。
- 建议：单独评估；或按需在源码写 `inline fn`（后端已支持真正内联）。列为 backlog。

## 已核实 / B2 结论

- **`emitConstAggregateStore` 端序（已核实，无 bug）**：目标端序为 **mcs51 小端 / mcs251 大端**
  （`std.Target.endian`），且**帧端序与目标端序一致**（`slotByte`：mcs251 大端、mcs51 小端）。
  故 `Value.writeToMemory` 的 `buffer[i]` 与 `frame[base+i]` 的对应在每个架构上都自洽：
  mcs51 = LE↔LE、mcs251 = BE↔BE。注意这与「全局/指针**内存**为大端（对齐 SDCC/C）」是两回事——
  内存↔帧才需要 `memByteDisp`。
- **B2（冷项整体压缩）——受设计限制，暂不可行**：
  - 冷**代码** `COLD` 在 Flash 中就地执行（XIP，如 `00FF022E`）；压缩后必须搬到 RAM 执行，
    而工具链（SDCC ASxxxx）与 AI8051U 均未提供「代码在 XRAM 运行」的机制；
  - 冷**数据** `COLDX` 由本后端输出为 `.ds`（**无初值**，本后端的全局初始化器尚不落地），
    Flash 里没有可压缩的内容。
  - 结论：`COLD`/`COLDX` 的**区域分离**已就位（可供外部工具做后置/裁剪），但「压缩 + 启动解压」
    在现有设计下没有落点，暂缓（若日后支持「常量冷数据 + 启动拷贝」再议）。
- **寄存器提升 / 跨块值级 CSE（暂缓）**：见 `docs/17`——asm 层的 A/slot 转发已被 `mcs_opt` 用尽；
  真正的寄存器提升需后端**寄存器分配**，跨块 CSE 需在后端做**可用表达式/支配**分析（每个 AIR 值
  已有唯一帧槽，理论上可把重复纯计算别名到首次结果）。属独立大项，风险高，暂缓。
- **C2 u32 运行期下标（核实：普通 Zig 不可达）**：mcs251 上 `usize` = **24 位**（= 指针宽度），
  普通 Zig 的 `arr[u32]` 因类型不匹配**根本编不过**（`unsigned 24-bit int cannot represent all
  unsigned 32-bit`），故 `runtime index is wider than a pointer` 在实践中不可达。仍把三处宽度检查
  放宽为防御性「≤ 4 字节」（地址只取低 `ptrBytes()` 字节，24 位地址空间），CI/QEMU 无回归。

xmake f --mcs_arch=mcs251 ; powershell -File tools\ci.ps1 -SkipUsb   # 含 mcs51 simtest ucsim
