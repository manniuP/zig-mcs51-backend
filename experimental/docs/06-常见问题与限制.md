# 06 常见问题与限制

## 1. 自举 Zig 后端的限制

以下特性尚未实现，会给出**明确的编译错误**（便于逐项补齐）：

- 浮点运算；
- **MCS-51** 目标：切片、变参、间接调用；
- 无界切片/指针的**运行期**下标：mcs251 已支持全局/固定地址数组的**四个数据空间**
  （data/idata/edata/xdata）与多字节元素/下标，以及**编译期切片**（`const s: []const u8 = &arr;`）
  的运行期下标 / `for` 迭代（见 §1.2）；仍未实现：**u32 下标**（4 字节 > 指针 3 字节）、MCS-51 切片。

其它已知约束：
- **`usize` 是 24 位**，不能作为 MCS 调用约定的函数参数/返回，前端的 extern
  校验会拒绝；跨语言接口请用显式定长整数（`u8`/`u16`/`u32`）。
- 跨模块**数据符号**（`extern` 变量）暂不支持；C 与 Zig 之间请只通过
  **函数**交互。
- 多参数跨语言的寄存器/栈分配尚未系统验证，建议单参数接口。
- Zig 后端目前**不发出** SDCC 的 `HOME`/`GSINIT`/`GSFINAL` 启动片段；
  独立链接需自带 `crt0-*.asm`，或改用 `sdcc` 驱动链接。

### 1.1 MCS-51 目标实测能力矩阵（2026-09-15，重建编译器 `zig-out/bin/zig.exe`）

| 特性 | 状态 | 证据/报错 |
| --- | --- | --- |
| 单标量参数 + 返回（`u8`→DPL，`u16`→DPL/DPH） | ✅ | `_inc16` 读 DPL/DPH 正确；blink 的 `led_next(u8)u8` 真机前仿真通过 |
| `comptime` 编译期求值 | ✅ | 常量折叠为 `mov a,#0x2d`；`compute(comptime n)` 被特化 |
| 分支/循环 + 多函数同文件 | ✅ | 构建层 `tools/fix_mcs_labels.py` 修标签后 sdas8051 通过 |
| **xdata 指针读/写**（`[*]T`，2 字节，DPTR+MOVX） | ✅ | 后端加 mcs51 分支：`buf[i]`、`@ptrCast(buf+i).*`、`buf+off`；`simtest` 的 `sum4(pbuf)=10` ucsim 通过 |
| **多参数**（`--stack-auto`） | ✅ | 参数0→DPL/DPH/B/A；参数2..N 由 caller 逆序压栈，callee 在入口 SP−(2+Σsize) 处读取。C↔Zig 双向、1~4 参 ucsim 通过 |
| **固定地址访问**（`@ptrFromInt(n).*`） | ✅ | 生成 `mov dptr,#n; movx`（xdata）；**落在 0x80–0xFF 时走 direct**：`mov a,dir8` / `mov dir8,a`（SFR，2026-09-15，见 §1.2） |
| **内联汇编**（`asm volatile ("...")`，无操作数） | ✅ | mcs251 后端实现 AIR `.assembly`：逐行加缩进原样输出，交给 sdas251。带操作数（`asm(… : : …)`）未实现 |
| **`inline fn` 内联** | ✅ | 后端原先丢弃 `dbg_inline_block`；现按 block 处理（`preallocInlineBlock`/`emitInlineBlock`）递归内联体 |
| **全局变量**（`var`/`extern` 数据） | ✅ | extern：Zig 经 `mov dptr,#_sym` 读写 C 的定义；Zig 定义：`Asx.updateNav` 在 `XSEG` 产出 `_sym: .ds N`，C 可读写。**零初始化**（非零初值需 XINIT 拷贝，暂缺） |
| 切片 | ❌ | `slices on MCS-51 are not implemented yet` |
| `u16` 乘法等 16 位运算 | ❌ | `2-byte multiply on MCS-51 is not implemented yet` |

> 说明：xdata 指针已可用（读/写都行），足以做 **C 传 buffer ↔ Zig 读写**。
> 其余（多参数、全局、切片、`@ptrFromInt`）仍需扩后端；重编方法见
> [07](07-调试笔记-ptr_rt自举崩溃定位.md)（系统 zig 0.16.0 重建）。
> 变通：多个参数打包进一个 `u16`/`u32` 标量。

### 1.2 纯 Zig 程序、SFR 直址与内联汇编（2026-09-15 真机通过）

目标 AI8051U（mcs251）。要点：

- **代码必须链到 `0xff0000`**：芯片程序存储器在 `FF:0000–FFFF`、复位 PC=`FF:0000`，
  链接加 `--code-loc 0xff0000`（xmake 各 mcs251 目标已加）。
- **SFR 直址**：`@ptrFromInt(0x80..0xFF)` 生成 `mov a,dir8` / `mov dir8,a`（非 MOVX）。
- **纯 Zig 启动**：`crt0.asm`（HOME 区）`ejmp __start; mov spx,#0x0100; ecall _main; sjmp .`；
  其中要**空声明 `PSEG/ISEG/BSEG` 区**，否则 sdcc 生成的 `.lk` 对这些区 `-b` 会报
  `No definition of area`。`.area` 是切换当前区，声明放代码前、最后再 `.area HOME`。
- **内联汇编**：`asm volatile ("...")`（无操作数）。可用 **comptime 拼字符串**做「宏」，
  配合 `inline fn` 把常量编进指令；`std.fmt.comptimePrint` 会把整个 std 拖进编译（后端编不了），
  应自己拼 `[N]u8`。
- **共享硬件宏库 `lib/mcs251.zig`**（推荐直接 `@import("mcs")`）：把 SFR 直址/位操作、各数据空间
  访问集中到一个可 include 的文件，带 `///` 文档与示例（zls 悬停可见）。构建时注入模块：
  `zig build-obj ... --dep mcs -Mroot=<源> -Mmcs=<仓库>/lib/mcs251.zig`，源码里 `@import("mcs")`
  （`@import` 不能越出模块根，故用命名模块而非 `../` 路径）。API：
  `sfrWrite/sfrOr/sfrAnd/bitSet/bitClr/bitCpl/sfrPtr/nop`
  与 `dataWrite/xdataWrite/idataWrite/dataPtr/xdataPtr`。
- **工程与目标**：`examples/ai8051u_zig_led`（`zigled`，纯 Zig 点灯）、
  `examples/ai8051u_zig_asm`（`zigasm`，用 `mcs` 宏做位操作）；
  两者 `zig → sdas251 → sdcc 链接`，真机 P1.1 LED 均以约 1Hz 闪烁。
  另有 `examples/ai8051u_uart`（`uart`，UART1 9600 @P3.1）与 `lib/uart251`。
- **手动指定数据空间**（`lib/mcs251.zig`）：
  - `data`(0x00–0x7F) 与 `SFR`(0x80–0xFF)：`@ptrFromInt(a)` 走 **direct**（`mov a,dir8`/`mov dir8,a`）；
  - `xdata`(≥0x100)：`@ptrFromInt(a)` 走 **MOVX**（DPTR）；
  - `idata`(间接 @Ri)：用内联汇编宏（`idataWrite`）；**读**需 A 回传，当前 inline asm 不支持操作数，
    故只提供写宏（读可用 data 路径）。
  注意地址必须是 `comptime` 常量才会走固定地址路径；变成运行期指针则退化为通用 24 位指针。
- **内存安全 / Zig 检查**（针对 `mcs251.zig` 这类宏）：
  - 编译期：参数是 `comptime u8`/`u3`，类型与范围由 Zig 编译期检查（位号 0–7、地址装得下 `u8`）；
  - 运行期：`@ptrFromInt(a)` **无检查**，本后端也不生成运行时安全检查；`asm` 对 Zig 透明
    （仅 `sdas251` 查语法）——地址/寄存器正确性靠程序员；
  - 这些宏操作的是**绝对地址（SFR/硬件）指针**，是 unsafe 逃逸口，普通变量的别名/边界保证不适用；
  - 建议：用 `*volatile`、地址保持 `comptime`、别把指针存进变量。
- **变量存储分配（已实现 `linksection`，2026-09-15）**：
  - 默认：全局变量 → `XSEG`(xdata)（`mov dptr,#_sym; mov dpxl,#(_sym>>16); mov a,@dpx`），
    局部变量 → SPX 栈（edata）。
  - 用 `linksection` 选空间（mcs251）：`var x: u8 linksection(".data")` → `DSEG`（**直接寻址**）；
    `.idata` → `ISEG`（`mov r0,#addr; mov a/@r0` **间接**）；`.xdata` → `XSEG`（24 位 `@dpx`，默认）。
    链接需 `--data-loc 0x30 --idata-loc 0x80`；crt0 里空声明 `DSEG` 区以匹配 `-b DSEG`。
  - **数据空间四分**（`@ptrFromInt` 与全局符号同规则）：`<0x100` **direct**；
    `0x100–0xFFFF` **edata**（16 位 `movx @dptr`）；`≥0x10000` **xdata**（24 位 `mov dpxl,#(sym>>16);
    mov a,@dpx`）。**注意**：早期版本对 ≥0x10000 只发 16 位 `movx @dptr`（丢高字节）——是 bug，已修。
  - `.data` 直接区只有 0x00–0x7F，且要避开 0x00–0x1F（寄存器组），故基址 0x30；
    初始化仍**只支持零初始化**。
  - **热/冷频次注解（2026-09-16）**：变量 `linksection(".hot")` → **DSEG 直接寻址**（快）；
    `.cold` → 独立 **`COLDX` 数据区**（xdata，慢无妨）。函数 `linksection(".cold")` 归入独立
    **`COLD` 代码区**（`Asx.updateNav`/`updateFunc` 按 `linksection` 选区，sdld 自动排到各自主区后），
    便于把冷代码/冷数据**整体压缩或后置**；热函数保持 CSEG（要真内联请直接写 `inline fn`）。
    **语法在返回类型前**：`fn f() linksection(".cold") T { … }`。
    验证：`examples/ai8051u_zig_hotcold/`（`xmake build zighotcold`）打印 `132a`；`hotcold.map` 里
    `_hot_cnt` 在 DSEG(0x30)、`COLDX 0x100xx`（`_cold_buf`）、`COLD 0xFF0xxx`（冷代码）各区独立。
  - **验证**：`examples/ai8051u_zig_mem/`（`xmake build zigmem`）写入**互不相同**的模式并回读比对，
    经 UART1(P3.1,9600) 打印；真机读到 `a1 ok  b2 ok  c3 ok  d4 ok`（data/idata/edata/xdata 全过）。
    比“灯闪”可靠（能暴露别名/寻址错误）。
  - 普通变量仍建议直接用编译器分配；`mcs251.zig` 的宏只用于**硬件绝对地址**。
  - **xdata 乐谱播放**（`examples/ai8051u_zig_buzz/`，`xmake build zigbuzz`）：无源蜂鸣器接
    P3.6（低电平触发），把乐谱（Timer0 重载值 hi/lo + 半周期数）写进 **xdata 数组**，
    播放时逐个读出驱动 Timer0 中断翻转 P3.6；真机正确播放《小星星》。
  - 顺带修/记录的后端问题：① 全局 xdata 数组元素偏移被忽略（`arr[i]` 全发 `#_arr`，已加 `off`）；
    ② **Zig→Zig 多参数调用只传第一个参数**（用 `inline fn` 绕开）；③ 不支持运行期变量下标。
- **运行期下标 + 运行期指针（mcs251，真机通过；空间推广 2026-09-16）**：后端支持两类物化：
  1. **编译期基址 + 运行期下标**：全局 `[N]u8` 数组或 `@ptrFromInt` 固定地址的 `buf[i]`（`i` 运行期）
     生成 `add a,#_buf; addc a,#(_buf>>8); …` 得到 `ptrBytes()` 字节绝对地址；**解引用按数据
     空间选寻址**（`.ptr_rt.space`）：`data`/`idata` = `mov r0,#…; mov a/@r0`、`edata` =
     `movx @dptr`、`xdata` = `@dr28`。
  2. **运行期指针 + 运行期下标**：`p[i]`（`p: [*]u8` 参数/变量）同样物化为
     `load(p) + i*elem_size`（元素大小 2..255 用 `mul ab` 缩放，下标可多字节）。
  另有**编译期指针物化**：把 `&全局数组`/`@ptrFromInt` 存入指针变量（如 `s_buf = buf`）会物化为
  帧内 3 字节地址（否则报 `unsupported constant operand`）。见 `CodeGen.zig` 的
  `preallocAbsElemPtr`/`emitAbsElemPtr`/`derefRead`/`derefWrite`/`materializeConstAddr`。
  **验证**：`examples/ai8051u_zig_rtindex/`（`xmake build zigrtindex`）四个空间各放一数组，运行期
  下标写入互异模式再回读，真机（AI8051U-34K64）打印 `a0b0c0d0 a1b1c1d1 a2b2c2d2 a3b3c3d3`；
  多字节元素（`u16`）/多字节下标（`u16`）经 QEMU 验证。
  限制：仅 **mcs251**；元素 1..255 字节；下标宽度 ≤ 指针宽度（3 字节）（`u32` 下标暂不支持）；均在帧槽内。
  **编译期切片**（`const s: []const u8 = &arr;`，无 AIR 指令）的运行期下标与 `for (s)` 迭代同样支持：
  把切片的全局/固定地址基址解析成视图，逐元素按空间寻址（`comptimeSliceOrigin`/`emitSliceElemValGlobal`）。
  验证：`examples/ai8051u_zig_slice/`（`xmake build zigslice`）三空间切片逐项读 + `for` 求和，
  真机打印 `102030 112131 … 172737`、`sum=9c`。
  顺带修复：**多字节标量写全局/固定地址/运行期指针的端序**——原按小端落盘而读回按大端
  （SDCC/C 也是大端），导致 u16 全局读写错位；现按逻辑字节 `i → 内存偏移 size-1-i` 写入。
- **结构体字段访问（mcs251，2026-09-15）**：后端实现 `struct_field_ptr` / `struct_field_ptr_index_N`
  与 `struct_field_val`（`CodeGen.zig` 的 `preallocStructFieldPtr`/`emitStructFieldVal` 等）。
  基址分三类：① **编译期基址**——局部对象（`.alloc`）折成帧内 `.ptr`，全局/外部符号与
  `@ptrFromInt` 折成 `ptr_rt{sym/imm_base, off}` 并在运行期物化 `base+off`（`emitConstPtrPlusOff`）；
  ② **运行期指针**（`*T` 参数、`@ptrCast`、字段里存/取的指针）——`.ptr_rt{base_addr, off}`，
  `emitElemPtr` 物化 `load(base)+off`，故可**链式**取字段（`a.b.c`）、对字段指针做运行期下标
  （`e.buf[i]`）；③ `struct_field_val`（对结构体**值**取字段）按父存储+偏移复制。
  字段偏移用 `Type.structFieldOffset`（与 `abiSize`/聚合内存布局一致）。
  另把**编译期常量指针解析**推广为递归 `resolveConstPtr`：沿 `.field`/`.arr_elem`/`.opt_payload`/
  `.eu_payload` 链累加偏移，最终归到 `.nav`/`.int`。这样**普通 Zig `struct`（非 `extern`）的全局
  字段也走通**——普通 struct 字段指针是 `.field` 链（此前只认 `.nav`/`.int` 直接基址，故只支持
  `extern struct` 全局）。限制：字段为 1~4 字节标量或聚合视图；切片类型字段值、运行期下标仍限 u8 元素。
- **COBS 库 `lib/cobs/`（平台无关，真机通过）**：把 COBS + 轻量日志帧抽成独立库，
  **只把编码结果写进调用方提供的缓冲区**，如何输出由调用方决定。两份等价实现：
  Zig `cobs.zig` 与 C `cobs.h`/`cobs.c`，**均可重入**：Zig 用 `Encoder` 结构体
  （`var e: cobs.Encoder; e.init(&buf); e.logBegin(...); …`，可同时多实例；`cobs_zig_test.zig`
  验证两实例交叉编码），并保留绑定模块级实例的免句柄 API（`cobs.logBegin` 等转发给 `s_enc`）；
  C 用 `cobs_enc_t` 句柄；两语言都有一次性编码 `encode`/`cobs_encode`。
  **代码尺寸坑（2026-09-15 真机定位）**：mcs 后端为每个**内联调用点**各生成一份代码；把
  `add`/`logRaw` 等全内联时，ziglog 单 `_main` 膨胀到 **~64KB**，顶满 AI8051U Flash，导致
  AiCube 报“超出文件大小、溢出移 EEPROM”，最大的 `msg` 段被截坏（现象：该帧首个 COBS 长度码
  变 `0x00`）。`Encoder` 方法改为普通 `fn`（非 `inline`）后 CSEG 降到 **~12.5KB**，六帧全部正常。
  **符号命名空间修饰（2026-09-16）**：函数符号改为按 **fqn** 生成（命名空间 → `_`，如
  `cobs.Encoder.encode` → `_cobs_Encoder_encode`），不再撞标签；导出名由 `Asx.updateExports` 以
  trampoline（`_main: ejmp _<mangled>`）提供，C/启动代码仍用短名。因此**模块包装可改为非 `inline`**
  （可据此继续瘦身）。验证：`examples/ai8051u_zig_ns/`（两个命名空间的同名 `foo`，真机打印 `020c`）。
  **据此做尺寸修复（2026-09-16）**：`lib/mcs251.zig` 的 `uartPutc`、`uartPutHex2` 由 `inline` 改为
  普通 `fn`（循环 / 半字节分支各一份，调用点 `ecall`）；另外后端**常量实参直接写 ABI 寄存器**
  （`mov dpl,#imm` / `push #imm`，省去 `mov a,#imm` 中转）。CSEG 实测（累计）：`zigmem` 6159→**1273**
  （-79%）、`zigns` 1792→**638**、`zigslice` 5444→**3112**；`ziglog` 10364→10381（COBS 主导，不变）。
  真机复验 `a1 ok b2 ok c3 ok d4 ok`。
  **激进尺寸等级（2026-09-16）**：`-OReleaseSmall`（xmake `--mcs_small=y`）启用后端**条件融合**
  ——比较紧跟 `cond_br` 时直接出分支，不物化 bool（`CodeGen` 的 `planFusion`/`fused_cmp`/`fused_br`）。
  **默认 `-ODebug` 输出与之前逐字节不变**。CSEG 再降：`zigmem` 1273→1190、`zigslice` 3112→**2784**
  （-10.5%）、`zigns` 638→587、`ziglog` 10381→10126。真机复验同前。
  **构建层瘦身工具 `tools/mcs_opt.py`（2026-09-15，无需重编 `zig.exe`）**：对 Zig→asm 产物做
  局部、可证明安全的改写，已由 `xmake` 在 `fix_mcs_labels.py` 之后自动调用：
  - **R1** 合并连续同向的 `inc/dec spx,#1|2|4` → 单条 `add/sub spx,#imm16`（帧大时省最多）；
  - **R2** 直块内值编号删冗余 `mov`；**R3** `mov a,X; mov Y,a` → `mov Y,X`；
  - **R4** A 为编译期常量时直接写目标寄存器（省「载入 A 再转存」）；
  - **R5** 回收无用代码/跳转：**R5a** `ejmp L` 紧跟 `L:`（跳到下一行）当空操作删掉；
    **R5b** 无条件转移之后、下一个标签之前的指令不可达，删掉。
  只在基本块内、不跨标签/分支/调用；未知指令一律当屏障。自测见
  `python tools/mcs_opt.py --self-test`（8/8）。实测（CSEG 字节，raw→opt）：
  `ziglog` 12563→10360（-17.5%）、**`zigmem` 10268→6155（-40%）**、`zigbuzz` 13825→11348（-18%）、
  `ptrtest` 2095→1838（-12%）；mcs51 `simtest` 761→753（-1%）。完整实测表与原因见
  [15-汇编瘦身工具mcs_opt](15-汇编瘦身工具mcs_opt.md)。
  验证：mcs51 `simtest`（ucsim）行为不变；**mcs251 真机（AI8051U）通过**——`ziglog` 六帧齐全
  （`boot/count/xy/cvar/msg/g16`）、`zigmem` 四空间 `a1 ok b2 ok c3 ok d4 ok`。
  帧 = `0x7E, id(2,LE), 参数…, XOR`，整帧 COBS 后以 `0x00` 定界；参数 u8/u16/u32 小端、
  `logVar`=LEB128、`logStr`/`logBytes`=`LEB128(len)+字节`。
  主机往返测试：`zig run lib/cobs/cobs_zig_test.zig`、`zig cc lib/cobs/cobs_c_test.c lib/cobs/cobs.c`。
  示例：Zig `examples/ai8051u_zig_log/`（`xmake build ziglog`）、
  C `examples/ai8051u_c_cobs/`（`xmake build ccobs`）；主机解码器 `decode.ps1`
  （先按 `0x00` 切帧、COBS 解码，再解析；**`.ps1` 要 UTF-8 带 BOM**）。
  真机读到 `boot` / `count n` / `xy 171,205` / `cvar n(LEB128)` / `msg "hello"` /
  `g16 n`（u16 全局自检，与 `count` 一致 = 端序修复）。详见 `lib/cobs/README.md`。
- **rzCOBS 暂缓**：defmt 的 rzCOBS 是**逆向、仅适合稀疏流**的变体（连续 7 个非零字节无法编码），
  其编码端在外部 crate；当前用标准 COBS 已足够。
- **中断**（`examples/ai8051u_zig_irq`，`zigirq`）：纯 Zig ISR + 内联汇编。
  - 向量表放在 `crt0.asm` 的 `HOME` 区（`crt0.asm` 里 `ljmp __start` 用 3 字节，
    给 `FF:0003`（INT0）让位；Timer0 在 `FF:000B` 放 `ejmp _t0_isr`）；
  - Zig 侧 ISR 是 `export fn`，用 `asm volatile` 保存 `ACC/PSW`、干活、`reti`（函数尾部
    的后端 `eret` 是死代码）；不带局部变量时后端不加栈帧，安全。
  - 真机：Timer0 中断里约 1Hz 翻转 P1.1 通过。向量地址见手册 15.3。
  - **⚠️ ISR 里不要直接写会产生栈帧的 Zig 代码**（这是「定时器中断跑了但很快崩」的常见根因）：
    ISR 若带局部变量/需要帧，后端会在函数头生成 `add spx,#N`、函数尾生成 `sub spx,#N; eret`；
    但 `reti` 会**跳过尾部 epilogue** → **每次中断 SPX 泄漏 N 字节**，栈最终撞坏。
    **正确写法**：ISR 只放「无帧」的内联汇编（存 `ACC/PSW` → `ecall _handler` → 恢复 → `reti`），
    真正的逻辑放普通 `export fn`（有完整 prologue/epilogue + `ret`）。
    例：`examples/ai8051u_zig_t0print`（`xmake build zigprint`）——Timer0 1ms 中断里每秒经 UART1
    打印一行；ISR `t0_isr` 无帧，`ecall _on_t0` 调用普通 Zig 函数完成打印。QEMU（`stc32g144k246`）
    与**真机 AI8051U-34K64**均实测输出 `t0\r\n` 每秒一行（真机 COM8@115200，行间隔 1.00s）。见 `docs/20`。
  - **UART 接收中断回环**：`examples/ai8051u_zig_uart_echo`（`xmake build ziguart`）——UART1 中断号 4、
    向量 `FF:0023`；ISR 无帧，逻辑在普通 Zig 函数里读 `SBUF`（`0x99`）再回写、清 `RI/TI`。
    **坑 1**：某些仿真模型读 `SBUF` 不清 `RI` → ISR 反复重入；显式 `anl SCON,#~1` 清 `RI`（与 STC `RI=0` 一致）。
    **坑 2**：PC 连续突发时，上一字节还没发完又写 `SBUF` 会**丢字节**（实测 `Ai8051U`→`Ai805U`）——
    需加**发送环形缓冲**（`ring[64]` + `tx_busy`；TI 里取队首续发）。加后 QEMU 与真机（COM8）
    对 `hello`/`Ai8051U`/`0123456789abcdef`/`The quick brown fox` 全部原样回显。
  - **ISR 不会被当死代码删**（`examples/ai8051u_zig_irq_all`，`xmake build zigirqall`）：把 Ai8051U
    **全部 55 个中断**各写一个 `export fn`（核心中断做运算、DMA/次要中断留空 `{}`），crt0 完整向量表
    引用；实测空 ISR 仍保留（每个一条 `eret`，`函数体=56、eret=55`，零 undefined）。依据：`export fn`
    是导出根，向量表引用让它可达；`mcs_opt` 只做函数内瘦身、`mcs_dce` 以 keep 文件引用为根且只删非
    keep 文件。做法：ISR 一律 `export fn` 并在向量表里引用。每个中断的**触发源**注释见
    `irqall.zig`/`crt0.asm`。

## 2. 编译/链接报错排查

| 现象 | 原因与处理 |
| --- | --- |
| `config.h: No such file or directory` | SDCC 的 `-I` 与路径必须**分开写**：`-I <dir>`，不能写 `-I<dir>` |
| `unrecognized file extension of parameter '…led.asm'` | `-femit-bin=` 的参数被 PowerShell 拆开了；改成整体引号 `"-femit-bin=…\led.asm"` |
| PowerShell 中文脚本解析报错（如 `CmdletBinding` 无法识别、全角括号报错） | `.ps1` 需 **UTF-8 带 BOM**；见 [04-驱动脚本用法](04-驱动脚本用法.md) 第 4 节 |
| 文件开头出现两次 `EF BB BF` | 重复加了 BOM；删掉多余的一份 |
| `ASlink-Error-No definition of area HOME`（`-b` 引用了不存在的区） | 独立链接别带 SDCC 库启动片段；或改用 `sdcc` 驱动链接 |
| `_main` 重复定义 | 自带 `crt0` 与 SDCC 启动库同时提供入口；二者只取其一 |
| 真机（AI8051U）烧录成功但程序不跑（P1 不动/高阻） | mcs251 代码链在了 `0x0000`。AI8051U 程序存储器在 **FF:0000–FFFF**、复位 PC=**FF:0000**，必须 `--code-loc 0xff0000`（`xmake.lua` 的 mcs251 链接步骤已加）。另外芯片上电 I/O 默认**高阻输入**，驱动前先配 `PxM0/PxM1` |
| `delay_ms()` 延时不对 | 目标主频与 `config.h` 的 `MAIN_Fosc` 不一致，用 STC-ISP 统一 |
| 位名（如 `ADC_POWER = 1`）编译失败 | 非 8 倍数地址的 SFR 位不能 `__sbit`；用掩码：`SFR \|= mask;` / `SFR &= ~mask;` |
| 指针参数写成了自己的栈帧（汇编是 `mov @spx-0xN,a`，没有 `@dr28`） | 对 `[*]u8` 参数**直接下标** `buf[i]` 会退化；改成单指针解引用 `(@as(*u8, @ptrCast(buf + i))).*`，即走 DR28 间接寻址。详见 [07](07-调试笔记-ptr_rt自举崩溃定位.md) |
| `sdas251` 报 `<m> multiple definitions` / `<p> phase error` | 同一 `.asm` 内多个**含分支**的函数，局部标签 `Lxx` 按函数从 0 重编号而撞名（编译器 bug）。**构建时已自动修复**：`tools/fix_mcs_labels.py` 会按函数给 `Lxx` 加前缀，`xmake` 与 `driver/build.ps1` 均已接入；手工用法 `python tools/fix_mcs_labels.py <file.asm>`（`--check` 只检查） |

## 3. 编码约定

- C/Zig 源码用 UTF-8；**注释可用中文，标识符保持 ASCII**。
- 含中文的 PowerShell 脚本必须 UTF-8 **带 BOM**。
- `write`/编辑工具写出的 `.md`、`.c`、`.zig` 无 BOM 即可（Markdown 与编译器
  都能正确处理 UTF-8）。

## 4. 调试抓手

- `blink.map`：符号地址、各区起始/长度（确认 `_main`、`_led_next`、`_delay_ms` 是否都在）。
- `*.lst` / `*.rst` / `*.sym`：汇编清单与符号表（核对参数寄存器、栈偏移）。
- `blink.mem`：内存占用概览。
- 未解析符号会在链接阶段报 `?ASlink-Warning-Undefined Global`，据此定位缺失的实现。

## 5. 何时改用 MCS-251

若需要切片、变参、间接调用或 24 位寻址，请切到 251 目标（见
[05-移植到MCS-251](05-移植到MCS-251.md)）；自举后端在 251 上的功能更完整。

## 6. 编辑器 / clangd（LSP）

C 头用 SDCC 关键字（`__sfr/__sbit/__at/__xdata/__interrupt…`），clangd 默认无法解析。
用 **`tools/clangd/sdcc_stubs.h`**（把关键字映射给 clang，**不参与真实构建**）+ 各工程根
`compile_flags.txt`（`-include` shim + `-I lib/include`，**不含** SDCC flag）即可消除红波浪线。

- 单行 `__asm … __endasm;`：shim 置空，源码用 `#ifndef __SDCC_STUB__` 给编辑器空实现
  （已用于 `mcs_intrins.h`）；**多行 asm**（`lib/mdu/mdu.c`）clang 仍会报错，可忽略或另加 guard。
- 两个现成 VSCode 工程：
  - `examples/vscode_c_cmake/` —— 纯 C，**CMake 驱动 SDCC**（`cmake/sdcc-mcs251.cmake`）。
  - `examples/vscode_mixed_xmake_zig/` —— C + Zig，**xmake 与 build.zig 各管一套、互不干扰**。
- 细节见 `tools/clangd/README.md`。

## 7. 能不能用 zig 编译 C / C++？（**不能**，C 走 SDCC）

**结论**：`zig cc` / `zig c++` **无法**为 mcs251 编译 C/C++；C 一律用 **SDCC mcs251** 编译
（`usb_cdc` 即如此），C++ 目前无可用方案。

**实测（重建后的编译器 `compiler/zig-out/bin/zig.exe`）**：
```
zig cc -target mcs251-freestanding -S hello.c
  → error: aro does not support compiling C objects yet
zig build-obj -fclang -target mcs251-freestanding hello.c
  → error: zig was compiled without Clang libraries
zig cc -target x86_64-windows-gnu -c hello.c          # 换个目标也一样
  → error: aro does not support compiling C objects yet
```

**原因**（代码依据）：
- `zig cc` 对**任何**目标都走自研 C 前端 **aro**；本版本 aro **尚未实现「生成目标文件」**，
  `src/Compilation.zig:5626` 直接 `failCObj("aro does not support compiling C objects yet")`。
- 当前编译器是 `have_llvm=false` 编译的：`src/Compilation/Config.zig:204` 无 LLVM → 强制 `.aro`；
  用 `-fclang` 也会得到 "zig was compiled without Clang libraries"。
- 即使重编时 `-Denable-llvm=true`（clang/LLVM 可用），**LLVM 没有 MCS-51/251 后端**；
  本仓库的 MCS 后端（`src/codegen/mcs/`）是 Zig 自研、只消费 **Zig AIR**，不经 LLVM。

**要支持需要二选一（都很大）**：
1. 给 **aro** 接一条到 MCS 后端（aro 产出 AIR/自研 IR 供 MCS 后端消费）；
2. 给 **LLVM 加 MCS-251 后端**（工作量大、成本高）。
在此之前，C 继续用 SDCC、C↔Zig 走已实现的共享 ABI（见 §1.1、`docs/03`）。
