# 17 - 后端 IR 提示 + 中间层优化（mcs_ir）

> 思路：**编译器只管输出「类 IR 提示」注释，值级优化交给中间层 `tools/mcs_ir.py`**
> （asm 文本级）。好处：优化迭代快，不必每次重编自举编译器。

## ★ 严重 bug（已修，2026-09-16）：`push/pop` 移动 SPX 致「文本偏移」误删

- **现象**：`ziglog` **真机 0 字节**、QEMU 乱码（一度误判为「QEMU UART 限制」）。
- **根因**：帧槽相对 **SPX**；`push`/`pop`（压栈传参、DR28 搬运）会移动 SPX，使
  **同一条逻辑帧槽在不同位置的文本偏移不同**。例（`cobs.Encoder.add` 调用处）：
  ```
        mov @spx-0x10,a      ; 存 3 字节指针的低字节（逻辑槽 -0x10）
        ...
        push acc             ; SPX 位移 +1
        mov a,@spx-0x11      ; 同一逻辑槽，文本偏移变成 -0x11
  ```
  全函数死槽规则**按文本偏移**判「从不被读」→ 把 `-0x10` 的 store 误删 → 真机/QEMU 坏。
- **最小复现**（二分定位）：仅删 `log_noir.asm:4238 mov @spx-0x10,a` 一条即复现。
- **修复**（`tools/mcs_ir.py`）：**含 `push`/`pop` 的函数整体跳过全函数死槽规则**
  （`_spx_moves`）；块内 DSE 已把 `push/pop` 当屏障，安全。新增自测用例。
- **验证**：`ziglog` QEMU + **真机（AI8051U，115200）**输出合法帧
  `03 7e 01 02 01 00 / 03 7e 02 … / 03 7e 03 04 ab cd …`；CI 全绿。
- **代价**：push 多的函数不再享受该规则（`ziglog +860`、`zigslice +124` 字节），
  `zigmem/zigns/zigbuzz` 不变。
- **教训**：凡「按 asm 文本假设帧布局」的优化，都必须先排除会移动 SPX 的指令；
  静态自测通过 ≠ 语义安全（该 bug 自测原本覆盖不到）。差分回归见
  `docs/session-2026-09-16-后端优化与mcs51修复.md` §真机复核。

## 提示格式

后端 `CodeGen.emitTrace` 在每条 AIR 指令前输出一行注释：

```
; v<inst> <tag> <操作数…> [-> @spx<disp>]
```

例：

```
; v2 add_wrap v0 c -> @spx-1
        add a,#0x03
        mov @spx-0x1,a
```

- `v<inst>`：AIR 指令号（值号）；操作数里的 `vK` 是值、`c` 是编译期常量。
- `-> @spx<disp>`：该值的结果帧槽（十进制位移）。
- 注释不影响 `sdas`；中间层消费后删掉。

## 中间层 `tools/mcs_ir.py`（夹在 `mcs_opt.py` 之后、`sdas` 之前）

按顺序**反复应用**以下规则至收敛（最多 12 轮），最后删掉全部 IR 提示注释：

1. **全函数死 store（帧槽从不被读）**：`mov @spx<d>,X` 若 `@spx<d>` 在**整个函数内从不被读**
   （只被写）→ 删；同一槽被写多次但从不读时，**这些 store 全删**。**必须扫全函数**：循环回边
   会让“store 之后的读”落在**地址更小**处（循环头读、循环尾写），只看后面会误删循环变量、
   程序直接跑飞。函数边界按全局标号 `_sym:` 划分；扫描时跳过注释行（避免提示里的 `@spx<d>`
   自证）。**计算本身保留**：`mcs_opt` 已把值留在 A，供后续指令直接用。

2. **基本块内死写（DSE，含“寄存器提升”效果）**：直线块内 `mov L,X`（L 为 `@spx<d>` 或
   `rN`）若**下一次访问 L 也是写**（值在被读前即被覆盖）→ 删。块以 标签/分支/调用/返回/
   `.area` 为界；遇到 `push/pop`、`spx` 调整、间接内存（`@rN/@dptr/@dpx/@dr28`）、未建模
   指令等**屏障**即停止（保守，不跨屏障删）。**读-改-写（如 `subb a,X`）算“读”**，不会误判。

3. **全函数死寄存器写**：`mov rN,X`（X 为寄存器/立即数/帧槽，无副作用）若 `rN` 在整个函数内
   从不被读（显式读、`push rN`、`@rN` 间接、`djnz/cjne` 等）→ 删。只处理 `r0–r7`（`a/b/dpl/
   dph` 可能是返回寄存器，不能仅凭“函数内未读”删除）；含未建模指令时放弃该函数（未建模可能
   隐式读寄存器）。

4. 删掉所有 IR 提示注释。

自测覆盖：循环回边、块内连续多写同槽、读-改-写、`push` 屏障、`@rN` 读地址寄存器、死
`mov r6,a`、寄存器被读须保留等：`python tools/mcs_ir.py --self-test`。加 `--stats` 打印指令数变化。

## 与 `mcs_opt.py` 的关系

`mcs_opt.py` 需把整行注释**附到上一条**（`_parse` 里 `entries[-1].raw += line`），
否则注释会变成新条目、**打断 R1/R3/R4/R5 的跨指令模式匹配**（相邻两条 `mov` 之间会被注释隔开）。

| --- | --- | --- | --- |
| `zigns` | 638 | 577 | **559** |
| `zigmem` | 1273 | 1217 | **1191** |
| `zigslice` | 3112 | 2921 | **2903** |
| `ziglog` | 10381 | 9883 | **9453** |
| `zigbuzz` | 11356 | 10968 | **10904** |
| mcs51 `simtest`(led.asm) | — | 250 | **248** 条指令 |

QEMU 复核：`zigmem`（`a1 ok b2 ok c3 ok d4 ok`）、`zigslice`（`102030 … sum=9c`）、
`zigns`（`020c`）、`zigrtindex`（`a0b0c0d0 …`）、`zighotcold`（`132a`）均正确；
CI（含 host COBS 测试 + mcs51 `simtest` ucsim）全绿。
`ziglog` 的 QEMU 串口输出本身即乱码（QEMU UART 时序问题，改动前/后都如此，非本工具引入），
故 log 以「规则安全性 + host COBS 测试」为准。

> **坑（必记）**：早期版本只扫 store **之后** → 漏掉**循环回边**（循环尾 store、循环头 read 在
> 地址更小处），误删循环变量 store，`zigmem` 直接不输出。现扫**全函数**：该槽从不被读才删；
> `--self-test` 含回边用例。
>
> **坑（必记）**：块内 DSE 的“下一次访问”判定里，**必须先判读再判写**。`subb a,X` 这类
> 读-改-写指令既读又写；若先判写会把它当成“覆盖”，从而把比较链的源值整条误删（曾致
> `zigbuzz` 比较链被拆、程序跑飞）。
>
> **坑（必记·`ziglog` 真机 0 字节）**：帧槽相对 **SPX**，而 `push`/`pop`（压栈传参、DR28 搬运）
> 会移动 SPX，使**同一条逻辑帧槽在不同位置的文本偏移不同**（例：`-0x10` 在 `push acc` 之后
> 读作 `-0x11`）。全函数死槽规则按**文本偏移**判「从不被读」，于是把 `-0x10` 的 store 误删
> （`ziglog` 的 `cobs.Encoder.add` 调用即中招）→ 真机/QEMU **0 字节或乱码**。
> 修复：**含 `push`/`pop` 的函数整体跳过该规则**（块内 DSE 已把 push/pop 当屏障，安全）。
> 复现/验证：`log` 修复后 QEMU 与真机（AI8051U，115200）均输出合法帧
> `03 7e 01 … / 03 7e 02 … / 03 7e 03 04 ab cd …`。代价：push 多的函数（`ziglog` +860、
> `zigslice` +124 字节）不再享受全函数 dse；`zigmem`/`zigns`/`zigbuzz` 不变。
>
> **纠正**：`docs/17` 早前把 `ziglog` 的 QEMU 乱码当作「QEMU UART 限制」——实为上述 `mcs_ir`
> 误删导致的真 bug，真机同样坏。

## 放置标签 + 优化等级 → 提示注释（2026-09-17）

后端 `link/Asx.zig` 对每个函数/数据符号输出一行注释，把 Zig 标签传给中间层：

```
; @tag func _opt_acc_fast  csegOfast
; @tag func _opt_acc_small coldOs
; @tag sym  _v_edata       edataO3
; @tag sym  _v_auto        autoO3
```

- 标签来自 Zig `linksection`（`lib/mcs251.zig` 导出 `m.data/idata/edata/xdata/exdata` 与
  `m.O0`…`m.O5`；可空格组合，如 `linksection(m.xdata ++ " " ++ m.O5)`）。
- **放置**（`device.parseSection`/`decide`）：`data`→`DSEG`、`idata`→`ISEG`、`edata`→`EDATA`
  （`movx @dptr`，251 片上）、`xdata`→`XSEG`（`@dpx` 24 位）、`exdata`→`EXDATA`（片外，需外接）；
  不写→按设备表自决（`≤2B`→`data`，否则默认空间）。
- **优化等级（与 GCC 对齐）**（`CodeGen.aggressiveSizeFor`）：`O0`–`O3`/`Ofast`→速度；`Os`→体积
  （函数并入 `COLD` 区）；未写→跟随全局 `-OReleaseSmall`。当前后端只有「体积/速度」一个开关，
  故 `Os` 与其余等级有别（受控实测 62 vs 68 条）；更多等级需再加旋钮。
- 中间层 `tools/mcs_ir.py` 解析并删除该注释（`--stats` 打印标签统计）；死代码清除见 `tools/mcs_dce.py`。
- **数据压缩/解压由用户自行实现**（工具链不做）。
- 示例：`examples/ai8051u_zig_opt`（`xmake f --mcs_arch=mcs251; xmake build zigopt`；
  QEMU/真机固定输出 `opt 11223344 060a`）。

## 优化回归（断言预算 + E2 差分，2026-09-18）

`tools/mcs_regress.py` 给文本级优化兜底，覆盖「CSEG 必须降到阈值」的**断言式**与
`base=fix+mcs_opt` vs `opt=+mcs_ir` 的 **E2 差分**：

- **差分**：构建时 `MCS_KEEP_BASE=1`（`xmake/helpers.lua`）会把 `mcs_ir` **之前**的 asm
  另存为 `<x>.asm.base`（已 gitignore）。`python tools/mcs_regress.py --auto <x>.asm`
  逐行比对 base 与最终 opt，断言 opt 只是 base **删行**（不许改写/新增/重排）、被删行只允许
  IR 提示 `; vN`、冷热标签 `; @tag`、`mov @spx<d>,X`、寄存器写；并**复刻优化迭代给删除归因**
  （`trace_deletions`）：`slot`=全函数死槽、`block`=块内 DSE、`reg`=死寄存器。
  **安全红线**：若含 `push/pop` 的函数里出现「`slot` 规则删帧槽 store」即判失败——这正是
  `ziglog` 真机 0 字节的历史 bug（帧槽相对 SPX，push/pop 移动 SPX 使文本偏移失真）。
- **预算**：内置各示例 opt 指令数上限（`BUDGETS`，实测 +约 10% 余量），可用
  `--budget <stem>=<n>` 覆盖；`--require-reduction` 断言确有削减。
- **自测**：`python tools/mcs_regress.py --self-test`（含 push 函数危险删除、改写、非法删行）。
- **CI**：`tools/ci.ps1` 设 `MCS_KEEP_BASE=1` 构建，再跑
  `mcs_ir/mcs_opt/mcs_regress --self-test` + 8 个示例的 `--auto --require-reduction` 预算检查。

```powershell
$env:MCS_KEEP_BASE="1"; xmake f --mcs_arch=mcs251; xmake build zigmem
python tools\mcs_regress.py --auto examples\ai8051u_zig_mem\mem.asm --require-reduction
```
