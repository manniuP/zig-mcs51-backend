# 13 8 位 / 32 位指令模式与 Flash 布局（AI8051U）

> 结论一句话：**AI8051U 是单核双模（8 位 8051 / 32 位 251），但只有一段 64K Flash、一个复位入口。
> 两种模式的固件不能并存/合并；切换 CPU 指令模式必须重烧对应模式的固件。**

## 1. 事实与证据

### 1.1 手册

- 程序存储器：**64K 字节，地址范围 `FF:0000H~FF:FFFFH`**，复位 PC = **`FF:0000H`**，
  中断向量也在 `FF:0003/000B/0013/001B/0023…`（AI8051U 手册 §12.1；特性表 “Flash 64K”）。
- 内核：“超高速 32 位 8051 内核（1T）”，支持 **8 位传统 8051 指令**与 **32 位（251）指令**两种模式，
  CPU 指令模式是**下载时的硬件选项**。

### 1.2 链接地址（本工具链）

| 目标 | 链接起始 | 证据 |
| --- | --- | --- |
| `-mmcs51`（8 位） | `HOME = 0x0000` | `blink.lk` / `uart.lk`：`-b HOME = 0x0000`；hex 首记录 `:030000 00 02004C` |
| `-mmcs251`（32 位） | `HOME = 0xff0000` | `ptrtest.lk`：`-b HOME = 0xff0000`；hex 首记录 `:02000004 00FF` |

### 1.3 实测（AI8051U-34K64）

- **32 位模式**：mcs251 固件（`ptrtest`/`zigmem`/`ziglog`/`ccobs`…）正常运行（串口有输出）。见 [06](06-常见问题与限制.md)。
- **8 位模式**：mcs51 `uart`（链到 `0x0000`）真机可跑，9600 打印 `tick` → 8 位模式确实从
  物理 Flash 起点取指、执行 8051 指令。
- **覆盖实验**：在 32 位模式下最后烧入 8 位固件（`uart_mcs51`）后，原 32 位程序 **不再运行**
  （9600/115200 均静默）→ 两者**共用同一个复位入口**，后烧入者覆盖前者的复位代码。
- 取消 ISP 的“擦除 EEPROM”选项**不改变**上述结论（该选项管用户 EEPROM 数据区，不改变代码复位入口）。

## 2. 含义

- `0x0000`（8 位 PC）与 `FF:0000`（32 位 PC）指向**同一段 64K Flash 的起点**，不是两个区域。
- 复位后取到的字节若与当前 CPU 模式指令编码不符，就会跑飞（静默/乱码）。
- 因此**不能**“把 8 位固件与 32 位固件并到一起”；同一时刻只能运行一种模式的一个固件。
- 切换模式 = 重新下载对应模式的固件（ISP 同时更新“CPU 指令模式”硬件选项）。

## 3. 想要“板上两种功能”的现实做法

1. **统一用 32 位（251）**：本工具链已能覆盖（C + Zig、指针/下标/COBS 等）。推荐。
2. **IAP bootloader**：只烧一份 32 位程序，把另一份固件当数据存高地址/EEPROM，运行期用 IAP
   自写 Flash 再重启——但从 8 位切 32 位（或反之）通常仍需 ISP/硬件选项介入，复杂且受限。
3. 若确实要两种模式，只能在需要时用 ISP **重烧**。

## 4. 8 位（mcs51）固件构建（逐个测用）

在仓库根：

```powershell
xmake f --mcs_arch=mcs51          # 8 位模式：链接到 0x0000
xmake build blink                 # -> examples\ai8051u_blink\blink.ihx     (P1 流水灯)
xmake build led                   # -> examples\ai8051u_led\led.ihx         (P1.1 闪)
xmake build uart                  # -> examples\ai8051u_uart\uart.ihx       (9600 打 tick)
xmake build simtest               # -> examples\at89c52_sim\simtest.ihx     (无串口，ucsim 用)
# 为不覆盖 251 版本，另存 *_mcs51.ihx 副本
xmake f --mcs_arch=mcs251         # 切回 251
```

- 纯 Zig 目标（`zigled`/`zigasm`/`zigirq`/`zigmem`/`zigbuzz`/`ziglog`）与 `ptrtest`/`ccobs`
  目前**只支持 mcs251**（后端限制），暂无 8 位版本。
- 8 位可观察性：`uart` 有串口；`blink`/`led` 看 P1；`simtest` 无串口，主要由 ucsim 验证
  （真机需自行加 P1/UART 指示）。

## 5. 代码空间与「超 64K」（手册 §2.27.6 / §2.30 / §2.37）

- 80251 的 **PC 是 24 位、代码空间 16M**；Keil 用 **Code Rom Size** 控制：
  - **Large**：总代码 ≤64K（`LCALL/LJMP`），复位/向量在 `FF:0000` 起。
  - **Huge**：总代码可达 **16M**（跨模块用 `EJMP/ECALL`）——只有 Huge 才能放 >64K。
- 手册 **§2.30.1 / §2.30.2** 分别是「≤64K / >64K 的**汇编**程序编写方法」。
- **§2.37**「程序超64K时如何设置保留 EEPROM 空间」：>64K 必须 Huge，并在 ISP 里设置避开
  EEPROM 区（该节示例是 **AI32G12K128**，EEPROM 固定 `FE:0000`）。
- **对 AI8051U-34K64**：物理 Flash 只有 **64K**，所以**即使 Huge 也放不下 >64K 代码**；
  它的 EEPROM 是这 64K 的**分区**（手册 §22.4），**不能靠 EEPROM 扩容代码总量**。
  本工具链 mcs251 固定 `--code-loc 0xff0000`（`FF:0000` 起，落在 64K 内），与此一致。
