# MCS-51 / MCS-251 组装与链接说明

> 本文原为 `driver/README.md`，已并入 `docs/`。文中的相对路径
> （如 `.\driver\build.ps1`、`tools/wsl_build_sdcc.sh`）均相对**仓库根**。

本文记录 SDCC 的编译/链接流程，以及 `build.ps1` 如何把 Zig MCS 后端的 ASxxxx 汇编
接进 `sdas` / `sdld`。

## 1. 三段式流程

```
Zig 源  --zig build-obj-->  .asm
        --sdas8051/sdas251-->  .rel
        --sdld (读 .lk)-->  .ihx / .map
```

## 2. SDCC 的真实命令（`sdcc -mmcs51 -V` 输出）

以 `sdcc -mmcs51 --model-large -V t.c` 为例，SDCC 依次执行：

```
sdcpp ... -xc t.c                      # 预处理 + 展开
sdas8051 -plosgffw t.rel t.asm         # 汇编
sdld -nf t.lk                          # 链接（命令文件）
```

其中 `t.lk` 内容（由 SDCC 生成）：

```
-muwx
-i t.ihx                 ; 输出 Intel HEX
-M                       ; 生成 .map
-b HOME = 0x0000         ; 各存储区基址
-b XSEG = 0x0001
-b PSEG = 0x0001
-b ISEG = 0x0000
-b BSEG = 0x0000
-k <libdir>              ; 库搜索路径
-l mcs51                 ; 启动/运行时库（顺序重要）
-l libsdcc
-l libint
-l liblong
-l libfloat
t.rel                    ; 显式输入对象
-e
```

要点：

- `sdld` 接受 `-nf <file>`：从命令文件读取选项与输入。
- `-b AREA = base` 设置**已存在**的存储区基址；若该区无人定义会报
  `ASlink-Error-No definition of area ...`。SDCC 的每个目标模块都会发出
  `.area HOME/GSINIT/...` 片段，从而把库里的启动模块拉进来并定义这些区。
- 库只在有**未解析符号**时按需拉入。Zig 后端目前不发出启动片段，因此独立链接
  时必须自带 `crt0`（见 `crt0-mcs51.asm` / `crt0-mcs251.asm`）。
- 代码区名为 `CSEG    (CODE)`，中断/复位等特殊区为 `HOME`、`GSINIT0..5`、
  `GSFINAL`、`RSEG`、`DSEG`、`ISEG`、`XSEG`、`PSEG` 等。
- 符号名带 `_` 前缀：C 的 `main` 在汇编里是 `_main`。Zig 后端在
  `src/link/Asx.zig` 里按此规则给函数名加 `_`。

## 3. MCS-251 端口差异

来自 `sdcc-c251/src/mcs251/main.c`：

```
_asmCmd  = { "sdas251", "$l", "$3", "$2", "$1.asm", NULL }
_linkCmd = { "sdld", "-r", "-nf", "$1", "$L", NULL }
_libs    = { "mcs251", libsdcc, libint, liblong, liblonglong, libfloat, NULL }
```

- 汇编器为 `sdas251`（MCS-251 指令与 24 位重定位）。
- 链接库多一个 `liblonglong`；启动库为 `mcs251`。
- 默认指令映射为 MCS-251 Source 模式；直接调用用 `ECALL`，返回用 `ERET`。
- 启动文件参考 `sdcc-c251/src/mcs251/tests/crt0.asm`：

```
__sdcc_gsinit_startup::
        mov     spx,#__start__stack - 1
        .area GSINIT2 (CODE)
        ecall   ___sdcc_external_startup
        mov     a,dpl
        jz      __sdcc_init_data
        ejmp    __sdcc_program_startup
__sdcc_init_data:
```

## 4. 库与内存模型

- 库按模型分目录：`<SDCC>/lib/<model>`，如 `large`、`huge`、`large-stack-auto`。
- 本仓库采用 **ABI rev2 + `--stack-auto`/`__reentrant`** 作为互操作约定
  （见 `sdcc-c251/doc/mcs251/abi.md`），因此互操作时应链接
  `mcs251-large-stack-auto` 一类库，并保证所有编译单元一致。

## 5. 构建 MCS-251 工具链

系统安装的 SDCC 4.5.20 只有 `sdas8051`，**没有** `sdas251`/支持 mcs251 的 `sdld`。
需先编译 `sdcc-c251`（WSL 脚本：`tools/wsl_build_sdcc.sh`，`configure` 后执行 `make`），
得到 `sdas251.exe` 与 `sdld.exe`，再用 `build.ps1 -Target mcs251 -Sdas ... -Sdld ...`。

## 6. 本驱动用法

```powershell
# MCS-51：使用系统 SDCC
.\driver\build.ps1 -Target mcs51 -Source .\examples\main.zig

# MCS-251：使用自建 sdcc-c251 工具
.\driver\build.ps1 -Target mcs251 -Source .\examples\main.zig `
    -Sdas <sdcc-c251>\bin\sdas251.exe -Sdld <sdcc-c251>\bin\sdld.exe
```

产物：`<Out>.asm`、`<Out>.rel`、`<Out>.lk`、`<Out>.ihx`、`<Out>.map`。

- `-UseSdccLibs`：按 SDCC 的 `.lk` 格式链接 SDCC 运行时库（需要 `-LibDir`）。
- 默认不带 `-UseSdccLibs`：只把 `CSEG` 放到 0x0000，配合自带 `crt0` 独立链接。

## 7. 尚待补齐

- Zig 后端尚未发出 SDCC 的 `HOME/GSINIT/GSFINAL` 启动片段，独立链接依赖自带 `crt0`。
- 符号修饰目前只做 `_` 前缀，尚未处理静态/模块前缀与 C ABI 的完整命名。
- 中断向量表、`__start__stack`、以及 `--xram-loc`/`--code-size` 等设备内存布局需按
  具体 STC 型号生成。
